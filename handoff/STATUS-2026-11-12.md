## 보강할 곳과 재개 순서

1. 학습 문서 테스트 시점 문구 정정 → 수락・develop 병합 → 전체 unittest 재실행. 이어 T-004 Sonnet high 개발 → 별도 S2 QA → S0 수락 순서로 진행한다.
2. T-004 QA 시작 때 Antigravity 새 계정의 첫 정상 응답과 모델 오류 유무를 확인한다. account list 활성 등록 및 T-004 QA 첫 정상 응답(msg_82057e3f6437)을 확인했다. 워커 보고 모델은 Gemini 3.8 Flash (Medium)이며 시작/첫 응답 오류는 관측되지 않았다. 최종 QA 결과는 대기 중이다. 실패 시 failedStage/원문 오류를 보고하고 중복 시작하지 않는다.
3. Phase 1 통합 spec을 발행한다. 실계정 검증은 사용자가 Instagram/X 각 1개 대상으로 기간 경계/중단 재개/획득 가능한 필드를 확인하고, AI는 비밀 없는 결과만 받는다. 현재 실제 계정 수집 범위/누락률/세션 복구는 확인 못 함.
4. Phase 2 프롬프트・판정 설계(Opus high) 후 구현(Sonnet medium)으로 나눈다. 15개 합성 정답은 실제 데이터 분포나 모델 성능을 증명하지 않는다. 사용자가 제공 가능한 비밀 없는 실제 사례와 출처 근거를 연결하고 평가용/개발용 자료를 분리하는 spec이 필요하다. known_concepts 초안도 사용자 지식 확인 후 개정해야 한다.
5. X 답글/인용/재게시 및 댓글 본문 포함 기준을 먼저 확정한다. 기간/언어/AI 관련성/관계 보존과 필터 이유를 테스트 가능한 계약으로 적어야 한다. 현재 요구는 미정이며 답글이 이미 올바르게 필터된다고 볼 수 없다.
6. None/0는 Store와 조회 경계에서 검증됐지만 수집 추출→분석→순위→화면 전 과정 보존은 확인 못 함. 실제 비공개/미제공/실제 0 표본과 수집 시각, 플랫폼별 상대 순위, 모든 값 결측/0일 때 확산도・신개념 대체 선정 기준을 별도 spec으로 검증한다.
7. 사건 묶기와 원문 추적/분석 이력・재개가 갖춰진 뒤 Phase 3 역공학 설계(Opus high)・구현, Phase 4 검문소/MCP 확장을 순차 발행한다. 제작 감독 반려 상한과 사람 검토 종료, 중복 발행 방지는 실제 출력으로 검증해야 한다.

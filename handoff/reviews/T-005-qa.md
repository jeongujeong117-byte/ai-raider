## 5. 4차 결함 재현 및 RED 회귀 기록 (FAIL, 반려 2회 정정)

### 5.1 결함 내용 및 원인
- **통합 후 실패 현상**: develop `67c8961` 통합 후 extras 전체 284개 테스트 실행 시, `test_16`에서 `json.decoder.JSONDecodeError` 발생 및 `test_18`에서 `rc 1 != 2` 실패 발생.
- **원인 분석**:
  - `tools/progress_check.py` 658행:
    ```python
    print(json.dumps(data, ensure_ascii=False, indent=2) if args.json else render_text(data))
    ```
  - `ensure_ascii=False`로 인해 JSON 문자열 내 비ASCII 유니코드 문자가 이스케이프되지 않고 그대로 출력 스트림으로 전달됨.
  - Windows 기본 콘솔/파이프 환경(`cp949`) 또는 `PYTHONIOENCODING=cp949:strict` 환경에서 실행 시, `OPEN_BUT_INTEGRATED`의 `evidence.board_status`에 저장된 Katakana 가운데점 `・`(`\u30fb`) 및 이모지(`\U0001F525`) 등이 cp949 코덱으로 인코딩될 수 없어 Python이 `UnicodeEncodeError: 'cp949' codec can't encode character '\u30fb'` 예외를 발생시킴.
  - develop의 `handoff/BOARD.md` 8행에 `S1 651cb84 완료・S2 QA 진행` 표기가 포함되어 있어, develop 통합 조건에서 이 코드가 실행될 때 실물 크래시가 유발됨.

### 5.2 기대 동작 vs 실제 동작
| 구분 | 계약 요구사항 (기대) | 실제 동작 (결함) |
|---|---|---|
| 종료 코드 | `exit 0` 또는 `exit 1` (정상/경고 점검 결과) | `exit 1` (Python 비정상 `UnicodeEncodeError` 예외 종료) |
| stderr | traceback 없이 깨끗한 고정 출력 | 원시 Python `UnicodeEncodeError` Traceback 노출 |
| stdout | 원문 텍스트/JSON 계약 준수 출력 | 빈 문자열 (호출자에게 JSONDecodeError 유발) |
| 인코딩 호환 | `cp949:strict` / UTF-8 모든 환경에서 안전 출력 | `cp949` 환경에서 실물 크래시 |

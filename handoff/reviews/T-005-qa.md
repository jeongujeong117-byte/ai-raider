## 4. 보안 및 아키텍처 한계 분석

1. **읽기 전용 허용목록 (Allowlist) 및 셸 인젝션 방어**:
   - `validate_git_args`와 `validate_orca_args`가 허용된 읽기 전용 하위 명령 조합만 엄격히 검증한다.
   - `subprocess.run(shell=False)` 실행 및 `resolve_executable` 내 `_SHELL_META` 거부를 통해 셸 메타문자 인젝션이 원천 차단된다.
2. **비밀 및 파일 내용 유출 방지**:
   - `WORKTREE_DIRTY`는 변경 항목의 개수(`entries`)만 집계하며, 변경된 파일 경로 및 파일 내용은 일체 읽거나 증거에 포함하지 않는다.
   - 외부 프로세스 오류 발생 시 원시 stderr는 폐기(`stderr=DEVNULL`)하고 표준화된 고정 오류 메시지만 출력한다.
3. **출력 한도(4MiB) 설계 한계 분석 (S1 한계 보고)**:
   - 현재 구현은 `subprocess.run`이 프로세스의 stdout을 메모리에 모두 수집한 후 `len(proc.stdout) > max_bytes`를 검사하여 `toolarge`를 판정한다.
   - **실제 동작**: 비정상 대용량 출력이 수신되면 검사 단계에서 안전하게 폐기되고 `CmdResult("toolarge")`로 격리되어 rc=2로 처리된다.
   - **잠재 위험**: 스트리밍 실시간 중단(kill) 방식이 아니므로, 악의적이거나 폭주하는 하위 프로세스가 수 기가바이트 이상의 출력을 스트림으로 쏟아낼 경우 메모리 사용량이 일시적으로 급증할 수 있다. 이는 현재 내부 Git/Orca CLI 환경에서는 현실적 위험이 낮으나 향후 외부 도구 연동 시 스트리밍 기반 버퍼 제한으로 보완이 권장된다.

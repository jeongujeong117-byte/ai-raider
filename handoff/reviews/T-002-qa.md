## 1. 1차 검증(1d65fa4) 결함 재현 및 2차 수정(6a64b95) 검증 요약

### 1.1. 1차 검증 (`1d65fa4`): FAIL (RED 재현 및 반려)
- **결함 내용**: 선언된 MCP JSON 정수 스키마 및 T-002의 "limit는 bool 제외 int 1~500, offset은 bool 제외 int >=0" 계약과 관련하여, FastMCP/Pydantic v2의 기본 lax coercion에 의해 잘못된 타입(bool, 문자열 수치)이 정상 정수로 강제 변환되어 `isError=False`로 성공 처리되는 검증 우회 결함 발생.
- **최소 입력 (공격 페이로드)**:
  - `list_posts`: `{"limit": True}`, `{"limit": "2"}`, `{"offset": False}`, `{"offset": "0"}`
  - `list_unanalyzed`: `{"limit": True}`, `{"limit": "2"}`, `{"offset": False}`, `{"offset": "0"}`
- **재현 명령**: `uv run --extra mcp python -m unittest discover -s tests/blackbox -v`
- **실제값 (1d65fa4)**: `limit=True`가 `1`로, `"2"`가 `2`로, `False`가 `0`으로 변환되어 `isError=False` 반환 → `AssertionError: False is not true : list_posts limit=True must be rejected as error` 발생 (QA 커밋 `e443091`로 RED 보존).

### 1.2. 2차 검증 (`6a64b95`): PASS (결함 해결 확인)
- **S1 수정 내역**: `raider_mcp.py` 도구 시그니처에 `pydantic.StrictInt`(`limit`, `offset`) 및 `pydantic.StrictStr`(`platform`, `handle`, `post_id`)을 적용하여 MCP stdio 경계에서 비엄격 타입 입력을 원천 차단.
- **QA 재검증 결과**:
  - `list_posts`, `list_unanalyzed`의 `limit`, `offset`에 bool(`True`/`False`), 숫자 문자열(`"2"`, `"0"`), float(`2.0`, `0.0`), `None` 전달 시 모두 Pydantic 검증 오류로 `isError=True` 반환 확인.
  - 정상 정수 경계값(`limit=1`, `limit=500`, `offset=0`): 정상 수행되어 `isError=False` 반환.
  - 식별자 필드(`platform`, `handle`, `post_id`): 정수형(`123`), 불리언(`True`), `None`, 리스트 전달 시 모두 `isError=True` 반환.

## 3. 필수 검증 항목별 세부 결과

### 3.1. `PostReader` 인터페이스 및 안전 격리
- **파일 미생성 및 Store 격리**: 존재하지 않는 DB 경로 전달 시 `FileNotFoundError`가 발생하며 파일 시스템에 새 파일이 생성되지 않음. `raider_mcp.py`는 `Store` 클래스를 임포트하거나 인스턴스화하지 않음.
- **읽기 전용 모드 및 뮤테이션 차단**: `mode=ro` 및 `PRAGMA query_only=ON`이 적용되어 `DELETE`, `INSERT`, `UPDATE` 시도 시 `sqlite3.OperationalError`로 즉시 차단됨.
- **연결 정리**: 쿼리 요청마다 `try...finally: db.close()`를 수행하여 윈도우 환경에서도 핸들 잔존이나 파일 잠금 누수가 발생하지 않음.

### 3.2. 조회 의미론 및 정렬/페이징
- **3단계 복합 정렬**: `posted_at DESC, platform ASC, post_id DESC` 정렬을 실증:
  1. `posted_at` 내림차순 최우선 (2026-03-01 > 2026-02-01 > 2026-01-01)
  2. 동일 `posted_at`일 때 `platform` 오름차순 (`bluesky` < `x`)
  3. 동일 `posted_at` 및 `platform`일 때 `post_id` 내림차순 (`post_90` > `post_10`)
- **페이징 및 total**: `total`은 `limit`/`offset` 적용 전 필터 조건과 일치하는 전체 레코드 수를 정확히 반영하며, `offset >= total` 시 `items=[]` 반환.
- **SQL 인젝션 방어**: `' OR '1'='1`, `'; DROP TABLE posts; --`, `' UNION SELECT ...` 등 악의적 페이로드가 파라미터 바인딩을 통해 리터럴 문자열로 안전하게 처리됨 (0건 일치).

### 3.3. 단건 조회(`get_post`) 및 플랫폼 격리
- 서로 다른 플랫폼의 동일 `post_id`(`x:common_id` vs `instagram:common_id`)가 완전히 독립적으로 조회됨.
- 미존재 글 조회 시 `None`(MCP JSON-RPC 상 `null`) 반환.
- 빈 문자열 `""`, 공백 `"   "`, `None`, 비문자열 전달 시 엄격 거부.

### 3.4. 미분석 조회(`list_unanalyzed`) 및 내결함성
- `post_analyses` 테이블 부재 시: 테이블을 임의로 생성하지 않고 전체 글을 미분석으로 정상 반환.
- `processing` 테이블(OCR/전사 이력)에 완료 상태가 있어도 AI 분석 완료로 취급하지 않고 미분석 목록에 유지.
- `post_analyses` 테이블 존재 시: `(platform, post_id)` 일치 행만 정확히 배제하며, 중복 행 및 NULL 행이 포함되어 있어도 오류 없이 안정 동작.
- 스키마 오류: `post_analyses` 테이블에 필수 식별 열(`platform`, `post_id`)이 누락된 경우 은폐하지 않고 명시적 `ReaderError` 발생.

### 3.5. 원문 보존성 및 오류 위생
- `{"likes": null}`과 `{"likes": 0}`이 왜곡 없이 각각 `None`과 `0`으로 보존됨.
- 빈 본문(`text=""`) 및 `text=None` 보존.
- 300,030자의 대용량 한글·이모지·유니코드 텍스트가 절삭이나 인코딩 왜곡 없이 원문 그대로 반환됨.
- 손상 JSON(`raw="{corrupt"`) 및 `posts` 테이블 부재 시 고정 안전 메시지(`stored post contains invalid JSON`, `database query failed`) 반환.
- 오류 응답 본문 및 로그에 파일 시스템 절대 경로, SQL 구문, 비밀, 스택 트레이스가 일절 노출되지 않음.
- stdout에는 순수 JSON-RPC 2.0 응답만 출력되며 배너/로그 오염 없음.

## 4. 무변경 보장 및 WAL 모드 실증 증거

### 4.1. 원문 DB 본체 및 스키마 불변 증거
- 다수의 MCP 도구 호출 전후로 SQLite 원본 파일의 바이트 해시(`sha256`), `st_mtime_ns`, `sqlite_master` 테이블 목록을 측정한 결과 100% 완전 일치함을 확인.
- `mode=ro`와 `query_only=ON`이 연결 레벨에서 강제되어 DB 파일 본체 및 스키마 변경이 원천 차단됨.

### 4.2. WAL 모드 최신 커밋 가시성 및 사이드카 관찰 사실
- **최신 커밋 가시성**: WAL 모드 DB에서 checkpoint 이전 WAL 파일에만 존재하는 커밋 데이터(`uncheckpointed_wal_2`)를 `mode=ro`로 정확하게 조회함을 실증 (`immutable=1`을 쓰지 않아 최신 데이터 누락 방지).
- **사이드카 관찰 사실과 원문 불변의 구분**:
  - SQLite WAL 모드 reader는 엔진 레벨의 프로토콜에 따라 shared memory 관리를 위해 디렉터리에 `*-shm`(32KB) 및 `*-wal`(0B) 파일을 생성/참조함.
  - 이는 SQLite WAL 아키텍처 상의 정상적인 운영체제 레벨 임시 사이드카 파일이며, 원본 DB 본체 파일(`*.sqlite`)의 내용, 바이트 해시, 테이블 스키마는 전혀 변경되지 않음.
  - 원문 DB 불변성과 디렉터리 내 사이드카 파일의 존재를 혼동하지 않고 명확히 분리 확인 완료.

1. **실제 프로덕션 DB 및 개인정보 미접근**: `.private/`, 실제 사용자 DB(`raider.sqlite`), 실제 SNS 로그인 세션은 사용자 정책에 따라 접근하지 않았으며, 전용 임시 SQLite fixture로만 검증함.

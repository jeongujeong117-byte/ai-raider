## 1. 판정 요약 및 반려 사유 (RED 재현)

선언된 MCP JSON 정수 스키마 및 T-002 명세의 "limit는 bool 제외 int 1~500, offset은 bool 제외 int >=0" 계약과 관련하여, FastMCP/Pydantic v2의 기본 lax coercion에 의해 잘못된 타입(bool, 문자열 수치)이 정상 정수로 강제 변환되어 `isError=False`로 성공 처리되는 검증 우회 결함을 확인하여 **FAIL**로 판정합니다.

### 1.1. 결함 세부 내역 (최소 입력 / 재현 명령 / 기대값 / 실제값)
- **재현 명령**:
  ```sh
  uv run --extra mcp python -m unittest discover -s tests/blackbox -v
  ```
- **실패 테스트**:
  `test_04_strict_mcp_type_validation_and_coercion_rejection (test_t002_mcp.BlackboxServerMcpProtocolTests)`
- **최소 입력 (공격 페이로드)**:
  - `list_posts`: `{"limit": True}`, `{"limit": "2"}`, `{"offset": False}`, `{"offset": "0"}`
  - `list_unanalyzed`: `{"limit": True}`, `{"limit": "2"}`, `{"offset": False}`, `{"offset": "0"}`
- **기대값**:
  T-002 타입 계약 및 선언된 정수 스키마에 따라, MCP 프로토콜 도구 호출 시 잘못된 타입이 전달되면 `isError=True` (오류 응답)를 반환해야 함.
- **실제값 (1d65fa4 동작)**:
  FastMCP/Pydantic v2의 기본 lax coercion에 의해:
  - `{"limit": True}` → `limit=1`로 변환되어 `isError=False` (아이템 1건 반환)
  - `{"limit": "2"}` → `limit=2`로 변환되어 `isError=False` (아이템 2건 반환)
  - `{"offset": False}` → `offset=0`으로 변환되어 `isError=False`
  - `{"offset": "0"}` → `offset=0`으로 변환되어 `isError=False`
  결과적으로 `AssertionError: False is not true : list_posts limit=True must be rejected as error` 발생.

### 1.2. 수정 방법 제안 (제품 코드 수정용 가이드 — QA는 제품 수정 금지)
S1 구현자는 `raider_mcp.py`에서 SDK가 정수 매개변수를 강제 변환하지 않도록 다음 방안 중 하나를 적용할 수 있습니다:
1. `from pydantic import StrictInt`를 임포트하여 FastMCP 도구 시그니처의 타입 힌트를 `offset: StrictInt = 0, limit: StrictInt = 100`으로 선언.
2. FastMCP 도구 함수 내부에서 `request` 인자 또는 Pydantic 모델의 strict 모드(`ConfigDict(strict=True)`)를 지정.
3. 도구 래퍼에서 클라이언트가 보낸 원본 JSON 타입을 엄격히 대조하여 bool 및 str이 정수 파라미터로 우회 진입하는 것을 차단.

## 3. 세부 항목별 검증 결과

### 3.1. MCP 경계 및 타입 검증 대조 결과
1. **문자열 식별자 검증 대조 (정상 차단 확인)**:
   - `get_post(platform=123, post_id="1")` → Pydantic `string_type` 오류로 `isError=True`
   - `get_post(platform="x", post_id=True)` → Pydantic `string_type` 오류로 `isError=True`
   - `list_posts(platform=123)` / `list_posts(handle=True)` → `isError=True`
   - **대조 결과**: 문자열 필드는 SDK가 int/bool을 문자열로 자동 변환하지 않고 엄격하게 거부함.
2. **정수 경계 검증**:
   - 정상 정수 경계값(`limit=1`, `limit=500`, `offset=0`): `isError=False`로 정상 성공.
   - 범위 밖 정수(`limit=0`, `limit=501`, `offset=-1`): `isError=True`로 정상 거부.
   - **결함 지점**: 오직 정수 필드(`limit`, `offset`)에 대해 SDK lax coercion(bool, str 허용)이 계약을 위반함.

### 3.2. PostReader Direct API 계약 (정상)
- Direct API(`reader.list_posts`)에서는 `_int` 함수에 의해 `limit=True`, `limit="10"`, `offset=False`, `offset="0"` 모두 정상적으로 `ValueError`를 발생시키며 철저히 거부됨.
- `Store` 클래스 미사용/미호출, 없는 DB 파일 시 `FileNotFoundError` 발생 및 파일 미생성 확인.
- `mode=ro` 및 `PRAGMA query_only=ON`에 의해 `DELETE`/`INSERT`/`UPDATE` 차단 확인.
- 요청 종료마다 연결이 닫혀 윈도우 환경에서도 파일 잠금 누수 없음.

### 3.3. 3단계 정렬, 원문 보존 및 안전 오류 위생 (정상)
- `posted_at DESC, platform ASC, post_id DESC` 3단계 정렬 및 사전 페이징 `total` 계산 정상.
- `likes=None` vs `likes=0` 구별 보존, 빈 본문 보존, 300,030자 대용량 유니코드 무절삭 보존.
- 손상 JSON 및 DB 쿼리 오류 시 고정된 안전 에러 메시지 반환 (경로, SQL문, 스택 트레이스 미노출).
- stdout에는 순수 JSON-RPC 2.0 응답만 출력되며, 배너나 print 문 프로토콜 오염 없음.

## 4. 무변경 보장 및 WAL 모드 실증 증거 (유지)

### 4.1. 원문 DB 본체 및 스키마 불변 증거
- MCP 호출 전후로 SQLite 원본 파일의 바이트 해시(`sha256`), `st_mtime_ns`, `sqlite_master` 테이블 목록을 비교한 결과, 100% 완전 일치함.
- `mode=ro`와 `query_only=ON`이 연결 레벨에서 강제되어 DB 본체 및 스키마 변경이 원천 차단됨.

### 4.2. WAL 모드 최신 커밋 가시성 및 사이드카 관찰 사실
- **최신 커밋 가시성**: WAL 모드 DB에서 checkpoint 이전 WAL 파일에만 존재하는 커밋 데이터(`uncheckpointed_wal_2`)를 `mode=ro`로 정확하게 조회함을 확인 (`immutable=1`을 쓰지 않아 데이터 누락 방지).
- **사이드카 관찰 사실과 원문 불변의 구분**:
  - WAL 모드 reader는 SQLite 엔진 레벨의 프로토콜에 따라 shared memory 관리를 위해 디렉터리에 `*-shm`(32KB) 및 `*-wal`(0B) 파일을 생성/참조함.
  - 이는 SQLite WAL 아키텍처 상의 정상적인 운영체제 레벨 임시 사이드카 파일이며, 원본 DB 본체 파일(`*.sqlite`)의 내용, 바이트 해시, 테이블 스키마는 전혀 변경되지 않음.
  - 원문 DB 불변성과 디렉터리 내 사이드카 파일의 존재를 혼동하지 않고 명확히 분리 확인 완료.

## 5. 확인하지 않은 부분 및 향후 절차

- **실제 사용자 DB/개인정보**: 테스트는 전용 임시 SQLite fixture로만 수행되었으며, 실제 DB 및 `.private/`는 정책상 접근하지 않음.
- **제품 코드 수정 금지 준수**: QA worker(S2)는 제품 코드(`raider_mcp.py`)를 일절 수정하지 않고 독립 검증 파일(`tests/blackbox/test_t002_mcp.py`)과 본 보고서만 갱신함.
- **향후 절차**: S1 구현자가 위 RED 재현 사항(SDK lax coercion 차단)을 수정한 새로운 구현 커밋을 작성하여 S0를 거쳐 배포하면 재검증을 진행함.

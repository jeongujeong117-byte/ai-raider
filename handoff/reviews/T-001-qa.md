## 대조 분석 및 권고 사항 (Observations & Recommendations)

### 1. `operation`이 `Blocked`를 발생시키며 `stop`이 설정된 경우의 fallback 호출
- **현상 관찰**: `run()` 수행 도중 `operation`이 `stop.set()`을 호출한 뒤 `Blocked`를 발생시키면, `base_supervisor.py`는 `except Blocked:` 블록에서 `_run_fallback(fallback)`을 즉시 실행하여 fallback 결과가 반환됩니다.
- **안전한 중단 의미 대조**:
  - `spec/T-001.md` 23행: `"중단은 SupervisorStopped를 올리고 추가 operation 호출 금지."`
  - `spec/T-001.md` 25행: `"Blocked는 BLOCKED_FALLBACK 기록. fallback이 있으면 한 번 fallback() 실행 후 결과 반환."`
  - 향후 fallback에 브라우저(Edge) 기동 또는 무거운 헤드리스 프로세스가 주입될 경우, 상위에서 중단(stop)을 요청했음에도 fallback이 실행되는 것은 "안전한 즉시 중단" 정책과 충돌할 수 있습니다.
- **권고 수정 방안**:
  `agents/base_supervisor.py`의 `run()` 메서드 내 `except Blocked:` 처리부에서 fallback을 호출하기 전 `if stop.is_set(): raise SupervisorStopped()` 검사를 선행하도록 보완하는 것을 권장합니다:
  ```python
  except Blocked:
      self._record(HealthState.BLOCKED_FALLBACK, "blocked")
      if stop.is_set():
          raise SupervisorStopped()
      return self._run_fallback(fallback)
  ```

### 2. 상태 파일 복원(`_load`) 시 `reason`의 고정 코드 화이트리스트 검증
- **현상 관찰**: `_load()`에서 `data["reason"]`의 타입을 `isinstance(data["reason"], str)`로만 검증하므로, 외부에서 손상되거나 임의의 문자열/비밀 토큰이 주입된 파일이 `ValueError` 없이 로드될 수 있습니다. (단, 이후 첫 연산 실행 시 고정 코드로 정화됨).
- **권고 수정 방안**:
  `base_supervisor.py` 모듈 상단에 유효한 reason 집합(`_VALID_REASONS = frozenset({"init", "ok", "rate_limited", "session_expired", "blocked", "fallback_used", "fallback_error", "fallback_rate_limited", "fallback_session_expired", "operation_error"})`)을 정의하고, `_load()` 검증 조건에 `if data["reason"] not in _VALID_REASONS: raise ValueError`를 추가하면 파일 오염에 대한 방어벽이 더욱 견고해집니다.

## 2. 세부 검증 결과 및 계약 공격 실증

### 2.1. 실제 config 정확한 5개 및 지정 aliases 검증 (`test_01`)
- `config/known_concepts.json` 파일 로드 시:
  - `schema_version`: 정확한 int 1
  - `provenance`: `"user_confirmed"`
  - `concepts`: `["환각", "프롬프트 엔지니어링", "컨텍스트 윈도우", "RAG", "임베딩"]` 정확히 5개, 순서 및 명칭 일치.
  - `aliases` 딕셔너리:
    - `"환각"`: `["hallucination"]`
    - `"프롬프트 엔지니어링"`: `["prompt engineering"]`
    - `"컨텍스트 윈도우"`: `["context window"]`
    - `"RAG"`: `["retrieval-augmented generation", "retrieval augmented generation", "검색 증강 생성"]`
    - `"임베딩"`: `["embedding", "embeddings"]`
- 미선택 개념(`파인튜닝`, `MCP`, `LoRA`, `양자화`, `에이전트 하네스` 및 영문 표기 `fine-tuning`, `Model Context Protocol`, `low-rank adaptation`, `quantization`, `agent harness`)이 concepts, aliases, `known_keys()` 어디에도 등재되지 않음을 확인.

### 2.2. 파일 I/O 읽기 전용 및 불변성 (`test_02`)
- `load_known_concepts(CONFIG_PATH)` 실행 전후 파일 SHA-256 해시 불변 확인 (`hashlib.sha256`).
- 존재하지 않는 경로 읽기 시도 시 파일 생성 없이 `FileNotFoundError` 발생.
- 빈 파일 및 손상된 JSON 파일 로드 시 예외 정상 전파 확인.

### 2.3. Dict 및 JSON 왕복 직렬화/역직렬화 무결성 (`test_03`)
- `model_validate` (Python dict) 및 `model_validate_json` (JSON 문자열) 왕복 시 한글 음절, 공백, 대소문자 변형 없이 100% 동일하게 복원됨을 확인.

### 2.4. Provenance 엄격성 공격 (`test_04`)
- 지원 provenance: `"user_confirmed"`, `"initial_synthetic_draft"` 2가지만 허용.
- 공격값(`"user_verified"`, `"synthetic"`, `"confirmed"`, `"draft"`, `""`, `"   "`, `None`, `123`, `True`, `False`)을 dict 및 JSON 양쪽에서 주입하여 모두 `ValidationError`로 차단됨을 확인.

### 2.5. schema_version 엄격한 int 1 및 bool 강제변환 차단 (`test_05`)
- Python `bool` 타입 상속 취약점(`isinstance(True, int) == True`)을 악용한 `schema_version=True`, `False` 주입을 `BeforeValidator(_exact_int)`가 완벽 차단.
- `1.0`, `0`, `2`, `-1`, `"1"`, `None` 등 비인가 버전 모두 거부 확인.

### 2.6. concepts 목록 공격 매트릭스 (`test_06`)
- 빈 목록(`concepts=[]`) 거부 (`min_length=1`).
- 비문자열 원소(`[1]`, `[None]`, `[True]`, `[{}]`) 거부.
- 공백/빈 문자열(`[""]`, `["   "]`, `["\t\r\n"]`) 거부.
- `strip().casefold()` 기준 중복 단어 차단 (`["환각", "환각"]`, `["환각", " 환각 "]`, `["RAG", "rag"]`, `["ß", "SS"]`).

### 2.7. aliases 하위 호환성 및 추가 필드 금지 (`test_07`)
- `aliases` 필드 생략 시 기본값 `{}`로 자동 세팅되어 과거 합성 JSON 포맷과의 하위 호환성 유지.
- `aliases={}` 명시적 빈 딕셔너리 허용.
- `extra="forbid"` 설정에 따라 비정의 추가 필드 주입 시 `ValidationError` 발생 확인.
- 딕셔너리가 아닌 타입(`[]`, `"str"`, `123`, `None`, `True`) 거부 확인.

### 2.8. aliases 키(canonical key) 제한 공격 (`test_08`)
- `concepts`에 없는 키(`{"LoRA": ["x"]}`) 거부.
- 대소문자가 일치하지 않는 키(`concepts=["RAG"]`일 때 `aliases={"rag": ["x"]}`) 거부.
- 공백이 포함된 키(`{" RAG ": ["x"]}`) 거부.
- 빈 문자열/공백 키(`{"": ["x"]}`) 거부.

### 2.9. aliases 값(alias list) 유효성 공격 (`test_09`)
- 리스트가 아닌 값(`"str"`, `123`, `None`, `{}`) 거부.
- 빈 리스트(`{"RAG": []}`) 거부 (S0 수락 규칙: 의미 없는 빈 배열 방지).
- 리스트 내 비문자열(`123`, `None`, `True`) 거부.
- 리스트 내 빈 문자열 및 공백 문자열(`""`, `"   "`, `"\t\r\n"`) 거부.

### 2.10. aliases 충돌 및 중복 공격 매트릭스 (`test_10`)
- 동일 canonical 내 중복 alias (`["retrieval", "retrieval"]`, `["retrieval", " RETRIEVAL "]`) 차단.
- alias가 자신의 canonical과 동일한 경우 (`{"RAG": ["rag"]}`, `{"RAG": [" RAG "]}`) 차단.
- alias가 다른 canonical과 동일한 경우 (`{"RAG": ["환각"]}`, `{"환각": ["rag"]}`) 차단.
- 서로 다른 canonical 간 alias 중복 (`{"환각": ["common"]}`, `{"RAG": [" COMMON "]}`) 차단.
- 유니코드 독일어 `ß`와 `SS`의 casefold 충돌(`{"RAG": ["ß", "SS"]}`) 차단.

### 2.11. validate_known_concepts의 canonical/alias 거부 및 불변성 (`test_11`)
- `new_concepts_detected`에 5개 canonical(`환각`, `프롬프트 엔지니어링`, `컨텍스트 윈도우`, `RAG`, `임베딩`)이 포함될 경우 각각 `ValueError` 발생.
- `new_concepts_detected`에 지정된 모든 alias 표기(`hallucination`, `prompt engineering`, `context window`, `retrieval-augmented generation`, `retrieval augmented generation`, `검색 증강 생성`, `embedding`, `embeddings`)가 포함될 경우 각각 `ValueError` 발생.
- 대소문자 및 공백 변형(`HALLUCINATION`, `  hallucination  `, `rag`, ` RAG `, `Context Window`, `EMBEDDING` 등) 모두 우회 없이 차단.
- `validate_known_concepts` 검증 실패 시에도 `AnalysisResult.new_concepts_detected`의 원본 문자열은 전혀 변형되지 않고 불변 유지.

### 2.12. 미선택 개념 및 기타 원문 개념의 신개념 허용 (`test_12`)
- 미선택 5종 및 영문 표기(`파인튜닝`, `MCP`, `LoRA`, `양자화`, `에이전트 하네스`, `fine-tuning`, `Model Context Protocol`, `low-rank adaptation`, `quantization`, `agent harness`)와 기타 미등재 기술 용어(`flash_attention`, `MoE`, `KV cache`, `스펙큘레이티브 디코딩`)는 원문 근거가 있을 경우 `validate_known_concepts`를 정상 통과 (오류 미발생).
- 사전 검사만을 수행하며, 자동 개념 추출이나 뜻풀이를 임의 생성하지 않음을 확인.

### 2.13. 원문 근거성 및 부분집합 규칙 유지 (`test_13`)
- `source_text`에 없는 개념이 `new_concepts_detected`에 있으면 `AnalysisResult` 생성 시 `ValueError`.
- `evidence_terms`에 없는 개념이 `new_concepts_detected`에 있으면 생성 시 `ValueError`.
- `evidence_terms`에만 기지식(canonical 또는 alias)이 언급되고 `new_concepts_detected`에는 신개념만 있는 경우 정상 통과 (원문 증거 단어로 기지식을 인용하는 것은 완전 허용).

### 2.14. 합성 골드 12개 fixture 불변 보존 및 독립성 (`test_14`)
- `tests/blackbox/fixtures/gold_samples.json` 파일의 `known_concepts` 12개(`transformer`, `lora`, `agent`, `ocr`, `asr`, `diffusion`, `fine-tuning`, `rag`, `vector_db`, `npu`, `vit`, `checkpoint`)가 수정 없이 100% 보존됨 확인.

- **직교 독립성 검증**:

# AI Raider 공통 작업 규칙

- 최상위 역할·절차는 `handoff/ROLES.md`를 따른다. 각 작업은 S0가 발행한 spec을 기준으로 수행한다.
- ROLES의 모델 정책은 기존 팀 구성/프롬프트 모델 표기보다 우선한다. 워커 시작 시 작업별 model/effort를 명시하고 spec 머리말에도 기록한다. Antigravity는 자체 설정 모델을 사용한다. 레드팀 2회 반려 시 3회차는 같은 워크트리에서 Opus high로 재시작하고, 3회차 FAIL이면 중단하여 '사람 검토 필요'를 보고한다.
- S0만 `handoff/BOARD.md`, `handoff/DECISIONS.md`를 수정한다. S0는 제품 코드를 구현하지 않는다.
- S1은 spec의 정확한 허용 경로만 수정한다. 범위 확대·설계 변경은 먼저 Orca `ask`로 S0에 질문하고 답을 기다린다.
- S2는 제품 코드와 기존 테스트를 수정하지 않는다. `tests/blackbox/`, 지정된 `handoff/reviews/` 보고서만 작성한다.
- S3는 `docs/learn/` 아래 설명 문서만 작성한다. 코드 수정 금지.
- AI 간 직접 연락 금지. 모든 전달은 S0를 거쳐 Orca orchestration으로 한다. 워커 터미널 직접 입력·폴링 스크립트 금지.
- `.private/`, 실제 세션 파일·쿠키·토큰·환경 비밀을 읽거나 출력하거나 커밋하지 않는다. Instagram·X 실제 로그인/수집은 실행하지 않는다. 테스트가 임시 디렉터리에 만드는 가짜 세션 fixture만 허용한다.
- 테스트·검증은 임시 데이터와 mock을 사용한다. 기존 사용자 DB와 미디어를 변경하지 않는다.
- 실패·미검증을 숨기지 않는다. 명령, 종료 코드, 테스트 수, 변경 파일, 미확인 사항을 보고한다. 비밀이 포함될 수 있는 원시 오류는 출력하지 않는다.
- S1은 시작 전과 완료 후 기존 전체 테스트를 실행한다. 기존 테스트의 삭제·skip·기대값 완화 금지.
- 의존성 설치: `uv sync --extra processing`. 회귀 검증: `uv run python -m unittest discover -s tests -v`.
- 자신에게 배정된 브랜치에 허용된 파일만 명시적으로 stage하여 커밋한다. `master` 병합·GitHub push 금지.
- 완료 시 지정 보고서에 커밋과 증거를 남기고 Orca `worker_done`으로 S0에 반환한다. 실패한 작업을 성공으로 보고하지 않는다.
- S0는 S2 PASS 후 전체 회귀 검증을 재실행하고 `develop`에 병합한다. 반려 3회 초과 시 중단하고 '사람 검토 필요'로 보고한다.

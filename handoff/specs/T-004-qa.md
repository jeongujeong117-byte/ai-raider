## 검증 기준
개발 브랜치의 handoff/specs/T-004.md 전체 계약을 따른다. S0의 QA spec은 develop에 별도 있으므로 이 텍스트를 자기완결 검증 지시로 사용한다. S1 보고서의 해석/성공을 정답으로 쓰지 않는다.

공개 API: core.analysis_schema의 AnalysisResult, KnownConcepts, load_known_concepts(path), AnalysisResult.validate_known_concepts(known)->None. strict 타입/추가 키 거부, 모든 필드 필수. version은 bool/float/문자열 아닌 정확한 int 1.

AnalysisResult 필드: schema_version=1, platform(7종 instagram/x/youtube/news/huggingface/github/gallery), post_id(비공백), track(standard/gallery), status(READY/HOLD), source_text(str), hold_reason(null/비공백), summary(list[str]), category(비공백), tags({technical_form,practicality,difficulty: list[비공백 str]}), event_id(null/비공백), evidence_terms/new_concepts_detected/concept_usage/actionable_idea(list[str]), is_pure_noise(strict bool). gallery는 gallery track, 나머지는 standard.

- READY: 원문 비공백, hold_reason=null. standard 요약 정확히 비공백 3줄, gallery 0~3줄. 중복/원문 근거 개념 검증은 casefold 비교. 새 개념은 evidence_terms 부분집합이어야 한다. 출력 문자열 원본을 변형하지 않는다.
- HOLD: hold_reason 필수. summary/세 tags 배열/네 분석 배열 모두 빈 배열, event_id=null, is_pure_noise=false. 빈 본문+미디어 대기는 잡담으로 오판하지 않는다.
- pure_noise=true면 네 분석 배열 evidence/new/concept_usage/actionable_idea가 모두 비어야 한다. 다른 READY 요약 규칙은 유지.
- evidence_terms/new_concepts_detected는 공백 원소/strip+casefold 중복 금지. 원문 없는 개념은 거부. 사전 대조는 별도 호출이며 strip+casefold로 등재된 용어를 new로 내면 거부.
- S1은 모든 목록에 공백 원소를 거부했다. S0는 의미 없는 추출 항목 방지로 이 제한을 수락하며 계약 완화로 보지 않는다.
- KnownConcepts: 정확한 int version=1, provenance='initial_synthetic_draft', concepts 비어 있지 않은 비공백 문자열 목록, strip+casefold 중복 금지. config 초안 12개는 기존 gold fixture known_concepts와 집합 일치. 실제 사용자 지식으로 확정된 사전 아님.
- load_known_concepts는 지정 파일만 읽는다. 없는/손상 JSON/잘못된 스키마를 숨기거나 파일 생성/덮어쓰기 금지. import만으로 I/O/네트워크 없음.

dict 및 실제 JSON 입력 경계에서 버전/boolean/문자열/float/null/누락/추가 키, 7종 platform/track, HOLD/READY/pure_noise 조합, 대용량 한글/이모지, casefold/앞뒤 공백, 근거/부분집합/사전 대조를 독립 검증한다. 임시 파일/DB만 사용한다. metrics는 스키마 밖이며 기존 Store/MCP None/0 보존 회귀를 유지한다. KST 경계/중단 재개/레이트리밋은 새 모듈 기능이 아니므로 기존 블랙박스 회귀로 확인하고 새 기능처럼 주장하지 않는다.

## 완료 증거
1. 전체 회귀 `uv run --extra processing --extra mcp python -m unittest discover -s tests` 및 독립 blackbox discover exit 0, skip 수 명시.
2. 기본 설치 검증은 별도 임시 venv 또는 안전한 uv sync로 실제 extras 부재를 확인한 뒤 수행한다. S1의 'extra 없음'은 같은 venv 잔존 가능성이 있어 증거가 불충분했다. pydantic 직접 의존성으로 새 API/47개 단위 테스트가 실제 기본 설치에서 동작하는지 검증하고 MCP 등 의도적 skip 수를 기록한다. 사용자 기존 환경/DB 훼손 금지.
3. PASS/FAIL, 명령/rc/수치/검증 대상 커밋/미검증을 보고서에 적고 허용 두 파일만 커밋 후 worker_done. FAIL이면 재현 명령/기대/실제를 보존하고 제품을 고치지 않는다. UI 없는 계약이므로 브라우저 검증 불필요.

## 계약
실제 config는 schema_version=1, provenance='user_confirmed', concepts=['환각','프롬프트 엔지니어링','컨텍스트 윈도우','RAG','임베딩'] 정확히 이5개로 교체한다. 합성12개는 tests/blackbox/fixtures/gold_samples.json에 그대로 두며 변경하지 않는다. 사용자 수준 기초 완료・중급 초입. 모델 KnownConcepts는 initial_synthetic_draft와 user_confirmed 둘 다 지원한다. 기존 synthetic 유효성/직접 API는 보존한다. T-004 스키마 version/strict/extra 금지/근거 검사 계약을 유지한다.

사용자 config에 aliases 키를 추가한다: dict[str,list[str]], canonical key는 concepts의 기존 원소에만 허용. aliases 기본값={}로 하여 기존 합성 JSON과 호환. 사용자 초기 alias:
- 환각: hallucination
- 프롬프트 엔지니어링: prompt engineering
- 컨텍스트 윈도우: context window
- RAG: retrieval-augmented generation, retrieval augmented generation, 검색 증강 생성
- 임베딩: embedding, embeddings

alias 원소 비공백 strict str, canonical/alias는 strip+casefold로 중복/다른 개념 충돌 금지. 같은 개념의 대소문자 표기는 자체 canonical 비교로 충분하므로 aliases에 중복 넣지 않는다. 사전 validate_known_concepts는 canonical/alias 어느 쪽으로 나온 이미 알려진 용어도 new_concepts_detected에서 거부한다. 출력값 변경 금지, 원문 존재/부분집합 검증은 실제 원문에 나온 표면형으로 그대로 유지한다. alias는 같은5개 개념의 표기만 늘리고 사용자 지식을 임의 확장하지 않는다.

파인튜닝/MCP/LoRA/양자화/에이전트 하네스는 미선택으로 모름. fine-tuning, Model Context Protocol, low-rank adaptation, quantization, agent harness 등 표현도 사용자 기지식 목록에 넣지 않는다. 위5개 및 그 밖의 원문 근거가 있는 미등재 개념은 신개념 후보로 허용해야 한다. 사전 검사만으로 자동 후보 추출이 구현됐다고 주장하지 않는다.

T-004 config=gold12개 동등 테스트는 새 사용자 config5개+provenance/aliases 검사로 교체하고, synthetic12개 유효성 검사는 gold fixture를 직접 읽어 별도 모델로 유지한다. 개정 이유와 이전/새 계약을 보고서에 적는다. 이는 사용자 승인된 계약 변경이며 기존 타입/근거 공격을 완화하는 것이 아니다. KnownConcepts의 빈 목록 지원은 이번 확정5개 처리에 필요 없으므로 기존 거부 유지. 한국어 뜻풀이 생성은 T-011/T-012의 후속 하네스이며 이번에 LLM/새 분석 필드를 만들지 않는다.

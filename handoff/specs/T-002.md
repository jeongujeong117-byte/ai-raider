## 인터페이스
- 공식 Python MCP SDK 사용. 설치 버전의 공식 문서/소스를 확인해 stdio API를 맞추고 근거를 보고한다. 기술 검색은 공식 1차 자료만 사용. optional extra `mcp`에 의존성을 추가하여 기본 수집 환경을 유지한다.
- `PostReader(db_path)` : sqlite3 URI mode=ro 및 query_only 사용. Store 생성자는 스키마 변경을 하므로 호출 금지. DB 없으면 FileNotFoundError, 자동 생성 금지. 연결은 요청 종료마다 닫는다. 테스트 임시 fixture만 읽는다.
- `PostReader.list_posts(platform='', handle='', offset=0, limit=100)` -> {'total':int,'items':list[dict]}. limit는 bool 제외 int 1~500, offset은 bool 제외 int >=0. 필터는 문자열만, 잘못된 입력은 ValueError. SQL 매개변수 바인딩. 정렬 posted_at DESC, platform ASC, post_id DESC. total은 페이지 제한 전 필터 일치 수.
- `PostReader.get_post(platform, post_id)` -> dict 또는 None. platform/post_id는 비어 있지 않은 문자열, 잘못된 입력 ValueError. 같은 ID의 다른 플랫폼 혼동 금지.
- `PostReader.list_unanalyzed(platform='', handle='', offset=0, limit=100)` -> 같은 목록 형식. 분석 이력 테이블이 없으면 모든 글이 미분석. 향후 `post_analyses`의 (platform,post_id)가 있으면 그 쌍은 제외(그 외 분석 필드 안 읽음). 테이블이 없다고 생성 금지. 있는데 필수 식별 열이 없으면 오류를 드러내고 전부 미분석으로 숨기지 않는다. processing은 OCR/전사이며 AI 분석 완료로 간주하지 않는다.
- 반환 post는 posts 기존 필드 platform/post_id/handle/url/posted_at/text/metrics/media/collected_at/raw 유지. JSON metrics/media/raw를 파싱하되 None을 0으로 바꾸지 않는다. 빈 본문·대용량 원문 보존. 손상 JSON은 명시적 오류. 원시 SQL 오류/DB 절대경로/비밀을 MCP 응답·로그에 노출하지 말고 고정된 안전 오류로 변환한다.
- `create_server(db_path)`가 MCP 서버 반환. 도구 이름 `list_posts`, `get_post`, `list_unanalyzed`로 정확히 등록. SDK 지원 시 readOnlyHint 등 조회 전용 annotation 설정. 수집/저장/실행 도구 없음.
- `main()`: `--db`(기본 core.common.DATA / 'raider.sqlite'), `--help`, stdio transport만. import만으로 DB/스레드/서버 시작 금지. stdout에는 프로토콜 외 로그 금지.

### 1차 검토 명확화
입력 타입 계약은 PostReader 직접 호출과 실제 MCP stdio 호출에 동일하게 적용한다. SDK lax coercion으로 bool/문자열/float를 int로 바꿔 통과시키지 않는다. list_posts/list_unanalyzed의 limit/offset은 strict int, platform/handle 및 get_post 식별자는 strict str로 검증한다. WAL sidecar의 SQLite 관리 동작은 DB 본문/스키마 쓰기와 구분하여 보고하되 최신 WAL 커밋을 누락시키는 immutable 옵션으로 대체하지 않는다.

## 완료 증거
1. 변경 전/후 전체 unittest 및 tests/blackbox discover exit 0. optional dependency 없는 기본 import/테스트도 검토한다. 기존 테스트 skip/완화 금지.
2. `uv sync --extra processing --extra mcp` 후 새 테스트 실행. 임시 SQLite로 빈 목록/단건 없음/같은 ID 다른 플랫폼/페이지/None·빈·대용량/SQL 인젝션 필터/잘못된 입력/미분석 table 없음·있음·오염/손상 JSON/없는 DB 검증.
3. 실제 SDK client로 임시 서버 stdio에 initialize/list_tools/call_tool 세 도구 검증. import 성공만으로 작동을 주장하지 않는다. stdout 프로토콜 오염 없음 확인.
4. 요청 전후 DB 해시/테이블/mtime 또는 동등한 증거로 쓰기 없음과 없는 DB 생성 없음 확인.
5. `uv run --extra mcp python raider_mcp.py --help`, wheel 새 모듈 포함, `git diff --check` exit 0.

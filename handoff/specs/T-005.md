## 공개 CLI 계약
`python tools/progress_check.py --repo <path> --run <id> [--orca-command <executable>] [--json]`.
repo 기본은 스크립트의 저장소 루트, run은 필수. orca-command 기본은 ORCA_CLI_COMMAND 환경값 또는 Windows orca, Linux orca-ide(ORCA_DEV_REPO_ROOT 설정 시 orca-dev). 실행파일 하나로 취급하고 셸 문자열 실행 금지. 상대/절대 repo 경로 검증. 명령별 timeout(기본 15초), 출력 한도 및 안전한 오류 처리를 둔다.

읽는 자료는 git worktree list --porcelain, 각 worktree status --porcelain, git log/ancestry/branch refs, 지정 repo의 handoff/BOARD.md 작업 표, 지정 Run의 orca orchestration task-list/worker-list --json뿐. 비밀 파일/사용자 DB/미디어/계정 CLI 접근 금지. shell=False로 실행하고 Windows 실행파일 해석은 설치된 Orca CLI 진입점을 확인해 안전하게 지원한다.

JSON 결과: {schema_version:1, observed_at:<UTC ISO>, repo:<path>, run_id:<id>, findings:[{code,severity,task_id,summary,evidence}], checks:[{name,status,detail}]}.
severity=info/warning/error, checks status=ok/unknown/error. task_id는 T-xxx 또는 null. exit=0 점검 완료・경고 없음, exit=1 불일치/경고 발견, exit=2 필수 소스 unavailable/잘못된 인자/파싱 실패. 실패를 정상으로 처리하지 않는다. 텍스트 모드도 동일 내용의 요약. 출력 stdout만 결과, raw 오류/비밀 가능 문자열은 출력하지 말고 안전한 고정 오류와 returncode를 제공한다.

검출 최소 항목:
- BOARD 현재 주 작업표에서 '병합 완료' 작업은 명시된 근거 커밋의 develop 조상 여부를 확인한다. 브랜치/커밋 해석 불명확하면 unknown, 허위 오류를 만들지 않는다. 역사 절/과거 '진행 중' 단어를 현재 상태로 오인하지 않는다.
- BOARD 현재 '진행/대기'이나 개발/QA 증거가 모두 통합됐다는 명확한 증거가 있는 경우 기록 불일치. Task 제목의 T-ID는 정확한 경계로 매핑하고 부분 문자열/이름만으로 통합 완료를 단정하지 않는다. 판별 못 하면 unknown.
- 반려 횟수 >=2 경고, dirty worktree 경고(파일 본문 읽지 않음).
- completed/succeeded 및 retained 완료 워커 화면 경고. liveness=unverifiable는 unknown으로 보고하며 멈춤/사망 판정하지 않는다. failed 이력만으로 재시도 권고 금지. T-002 과거 FAIL 정정 이력은 최종 작업 실패와 구분하며 근거 부족 시 unknown.
- 시작 후 응답 없음/오래 멈춤/테스트 감소/승인 없는 master 변경・push 여부는 허용 자료에 직접 증거가 없으면 unknown. 시간만으로 실패를 단정하지 않는다. 명시적 master 기준 0be384f와 비교하되 변경=승인 없음으로 단정하지 않는다. 원격 네트워크 호출이나 승인 추정 금지.

사용자 지식/수집 내용 등 제품 데이터는 검사 대상이 아니다. 자동화가 가능한 범위와 S4 사람형 감사가 필요한 범위를 보고서에 분명히 적는다.

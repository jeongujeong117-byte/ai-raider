# T-000 · 독립 블랙박스 검증

## 역할 및 모델

S2 레드팀, Antigravity 자체 설정 기본 모델/effort 사용(사용자 정책의 명시적 예외). 너는 AI Raider의 블랙박스 검증관이다. 구현 코드를 믿지 말고 아래 인터페이스와 완료 증거를 기준으로 공격한다. 제품 소스와 기존 테스트 수정 금지. 모든 연락은 S0를 거쳐 Orca orchestration으로 한다. `handoff/AGENTS.md`와 ROLES의 보안 규칙을 따른다. 최신 사용자 정책상 S1은 Sonnet medium이고, 2회 반려 후 3회차 Opus high, 3회차 FAIL은 사람 검토 필요다.

## 외부 인터페이스와 기대 동작

- `uv run python raider.py --help`, 기존 serve 명령 및 ai-raider console entrypoint를 유지한다. 실제 서버는 loopback과 임시 저장소에서만 검증한다.
- `core.store.Store(path=None)`는 connect/save/create_run/tasks/task/run_state/rows를 제공한다. 기존 raider.Store, Registry, Processor, SourceAgent, GithubAgent 및 루트 7개 모듈 import도 호환된다. 기존 테스트 monkeypatch 지점도 보존돼야 한다.
- post 예: dict(platform='instagram', post_id='fixture', handle='test', url='https://example.com/p', posted_at='2026-08-08T15:00:00+00:00', text='', metrics={'likes':None}, media=[], raw={}). 임시 DB에 저장·재저장하면 total=1, text='', likes=None이고 0으로 오염되지 않는다.
- window('2026-08-09','2026-11-09')는 now=2026-11-11 UTC 고정 시 시작 2026-08-08T15:00:00+00:00, 종료 2026-11-09T15:00:00+00:00이다. 경계 전후를 시험한다.
- 중단 후 재개해 같은 글을 다시 받아도 중복 저장되지 않으며 완료 작업은 건너뛴다. mock 수집기의 레이트리밋/오류는 안전한 상태로 표시하고 원시 비밀을 메시지에 내보내지 않아야 한다. 이번 작업은 새 재시도/상태 4종 정책을 추가하는 작업이 아니다.
- 대용량 본문과 여러 게시물은 잘리지 않고 저장·조회된다. 규모와 실행 시간을 보고한다.
- core.store/core.post_processing/core.media_store 및 agents의 instagram/x/youtube/news/gallery/huggingface/github 모듈은 개별 import 가능하며 import만으로 서버·실수집을 시작하지 않는다.
- ROOT는 프로젝트 루트이고 설정·web·data 경로를 이동 폴더 안에서 찾으면 안 된다. 기존 HTTP 경로·JSON 형식·오류 처리·날짜/반응/미디어 처리 의미를 유지한다.

## 필수 완료 증거

1. `uv sync --extra processing`, `uv run python -m unittest discover -s tests -v` : 기존 50개 테스트 exit 0. 기존 테스트 수정 금지.
2. 작성한 블랙박스 테스트를 `uv run python -m unittest discover -s tests/blackbox -v`로 실행. None/빈 본문/KST 경계/재개 중복/레이트리밋 mock/대용량을 모두 시험하고 결과를 보고한다.
3. `uv run python tests/smoke_http.py` exit 0. 이는 가짜 수집기·임시 저장소만 사용한다. 실제 네트워크 수집 스크립트 실행 금지.
4. CLI --help와 모듈별 import exit 0. wheel에 core/agents와 console entrypoint가 포함되는지 메타데이터 확인 및 임시 설치 환경에서 `ai-raider --help` 확인. 설치가 불가하면 차단 원인을 정확히 보고한다.
5. 화면이 있는 앱이므로 임시 저장소·수집 mock으로 loopback 서버를 띄우고 Orca 브라우저로 실제 화면을 확인한다. 먼저 `orca skills get orca-cli`를 읽고 그 가이드대로 한다. SNS 로그인·수집 버튼은 실행하지 않는다. 실제 사용자 data/.private를 읽는 서버를 시작하지 말고 임시 경로와 가짜 객체를 주입한다. 화면이 안 뜨거나 브라우저가 불가하면 미검증을 명시한다.
6. `git diff --check`, 변경 파일 목록 확인. 검증 후 자신이 시작한 임시 서버만 종료한다.

## 보안 및 범위 밖

`.private/`, 실제 세션 파일·쿠키·토큰·환경 비밀 읽기/출력/커밋 금지. Instagram/X 실제 로그인·실계정 수집 금지. 테스트가 임시 경로에 만드는 가짜 세션 fixture만 허용. 외부 수집·master 병합·push 금지. 개선 구현은 하지 않는다. 실패한 항목을 기존 테스트 수정이나 skip으로 통과시키지 않는다.

## 보고 및 반환

`handoff/reviews/T-000-qa.md`에 PASS 또는 FAIL, 검증 대상 커밋, 명령·종료 코드·테스트 수, 필수 사례별 결과, 화면 검증 근거, 미검증 사항을 적는다. FAIL은 재현 명령/기대값/실제값을 포함하고 수정 방법은 제안만 한다. 필수 완료 증거가 확보되지 않으면 PASS라고 쓰지 않는다. 허용한 QA 파일만 커밋하고 Orca worker_done으로 판정·브랜치·커밋·보고서 경로를 S0에 반환한다.

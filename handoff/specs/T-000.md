# T-000 · 기존 동작을 유지하는 core/agents 분리

## 역할

너는 AI Raider 프로젝트의 S1 구현 담당(Claude Opus)이다. `handoff/AGENTS.md`와 이 spec만 작업 지시 기준으로 삼는다. 수정 허용 파일 밖은 절대 고치지 않는다. 필요하면 수정하지 말고 보고서의 '범위 밖 필요 사항'에 적는다. 설계를 바꾸고 싶으면 구현하지 말고 Orca ask로 S0에 질문한다. 기존 테스트가 전부 통과해야 한다. 완료 시 커밋하고 지정 보고서를 작성한다. '확인 못 한 부분'을 비워 두지 않는다.

## 목표

루트에 섞여 있는 저장소·미디어 처리·7개 정보원 수집 구현을 `core/`, `agents/`로 분리하고 기존 실행·저장·조회·중단/재개 동작을 유지한다.

## 인터페이스

- 기준 `develop`의 `0be384f` 제품 동작을 보존한다. 서버는 `raider.py`에 두며 `uv run python raider.py serve`와 `ai-raider = raider:main` 계약을 유지한다.
- `core.store.Store(path=None)`에 기존 Store 구현을 옮긴다. `connect()`, `save(post)`, `create_run(selected, begin, finish, download_files=False)`, `tasks(run_id)`, `task(row, state, seen, message='')`, `run_state(run_id, state)`, `rows(platform='', handle='', offset=0, limit=100, sort='date', category='')` 계약과 SQLite 스키마를 유지한다.
- 저장/조회 예: `metrics={'likes': None}`, 빈 `text=''`, `media=[]`를 가진 post를 저장·재저장해도 total=1이고 조회 likes는 None이다. 새 필수 필드를 요구하지 않는다.
- `core.post_processing`, `core.media_store`에 기존 구현을 이동한다. 함수·클래스 인자/반환/예외 의미를 유지한다. 공통 보조 구현도 허용 경로에서만 분리한다.
- 각 플랫폼 구현은 대응하는 `agents/*_agent.py`에 둔다. 기존 `instagram(task, begin, finish, stop)` 동기 generator, `x_posts(task, begin, finish, stop)` 비동기 generator, `YoutubeExtractor/NewsExtractor/GalleryExtractor/HuggingFaceExtractor.collect(target, settings, stop)`, `GithubAgent` 및 공통 `SourceAgent` 계약을 보존한다.
- 루트 `raider`, `source_agents`, `github_agent`, `post_processing`, `media_store`, `source_tools`, `source_manager`의 기존 공개 import와 기존 테스트의 monkeypatch 지점이 그대로 작동해야 한다. 루트에는 얇은 호환 위임/재노출만 남길 수 있다. 같은 실제 로직을 복사해 두지 않는다. 순환 import를 피한다.
- ROOT는 저장소 루트를 계속 가리켜야 하며 이동된 파일의 폴더를 데이터 루트로 쓰면 안 된다. 테스트에서 raider.ROOT/DATA/PRIVATE/now/instagram 및 기존 모듈의 의존성을 patch하는 계약도 유지한다. 기존 테스트 자체를 변경해서 해결하지 않는다.
- KST 날짜 경계: `window('2026-08-09','2026-11-09')`는 고정 now=2026-11-11 UTC에서 `2026-08-08T15:00:00+00:00` 이상, `2026-11-09T15:00:00+00:00` 미만이다.
- 7개 agents 모듈을 각각 import할 수 있고 import만으로 서버·스레드·실수집을 시작하지 않는다. 독립 수집 CLI의 신규 설계는 이번 범위가 아니다.
- 모든 기존 HTTP 경로·JSON 응답·기존 데이터 재사용·오류의 비밀 제거·반응 결측값·중단 후 재개/중복 방지를 유지한다.

## 완료 증거

1. 변경 전 `uv sync --extra processing`, `uv run python -m unittest discover -s tests -v`를 실행하고 기준 테스트 수와 결과를 기록한다. 설치 실패는 정확한 원인과 영향만 보고하고 성공으로 간주하지 않는다.
2. 변경 후 동일한 전체 테스트 명령이 exit 0, 기존 테스트 전부 통과여야 한다. skip/삭제/완화 금지.
3. `uv run python tests/smoke_http.py`가 임시 저장소·가짜 수집기를 사용하여 exit 0이어야 한다. 실제 네트워크 수집 스크립트는 실행하지 않는다.
4. `uv run python raider.py --help`가 exit 0이고 기존 CLI를 표시해야 한다.
5. `uv run python -c "import core.store, core.post_processing, core.media_store; import agents.instagram_agent, agents.x_agent, agents.youtube_agent, agents.news_agent, agents.gallery_agent, agents.huggingface_agent, agents.github_agent"`가 exit 0이어야 한다.
6. 패키지 설정이 새 패키지를 포함함을 빌드 산출물 또는 동등한 설치 증거로 확인한다. 검증용 임시 산출물은 커밋하지 않는다.
7. `git diff --check` 통과, 허용 경로만 변경. 명령별 종료 코드와 테스트 수를 보고한다. non-zero 검증은 작업 실패/미완료이며 숨기지 않는다. 기존 결함 발견 시 범위 밖 보고하고 S0에 질문한다.

## 범위 밖

상태 4종·자동 우회·레이트리밋 재시도 정책 신규 구현, MCP, AI 분석/harnesses, UI 변경, DB 마이그레이션, 새 CLI 옵션, 의존성 추가/업데이트, 실계정 로그인 검증, 외부 push/master 병합은 하지 않는다. 수집 로직을 개선하거나 기존 결함을 몰래 고치지 않는다.

## 보고

허용 파일만 명시적으로 stage하여 개발 브랜치에 구현과 `handoff/reports/T-000-dev.md`를 커밋한다. 보고서는 결과, 변경 파일, 이동 대응표, 실행 명령·종료 코드·테스트 수, 호환 검증, 확인 못 한 부분(필수), 범위 밖 필요 사항을 포함한다. 마지막에 Orca worker_done으로 브랜치명·커밋·보고서 경로·검증 요약을 S0에 반환한다. BOARD/DECISIONS를 수정하거나 다른 AI에 직접 연락하지 않는다.

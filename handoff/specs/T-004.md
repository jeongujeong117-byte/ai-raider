## 인터페이스
`core.analysis_schema`에 pydantic v2 `AnalysisResult`, `KnownConcepts` 모델 및 `load_known_concepts(path)`를 제공한다. 모델은 extra='forbid', 엄격 타입 검증으로 bool/숫자 문자열 강제 변환을 거부한다. import만으로 파일 읽기/쓰기/네트워크 작업 없음.

AnalysisResult JSON v1 필드(모든 필드 필수, 명시적 null 허용 항목만 nullable):
- schema_version: 정수 리터럴 1; platform: instagram/x/youtube/news/huggingface/github/gallery 중 하나; post_id: 공백 아닌 문자열.
- track: standard/gallery. gallery 플랫폼은 gallery track, 나머지는 standard track만 허용.
- status: READY/HOLD. source_text: 원문+OCR+전사를 호출자가 합친 문자열(빈 문자열 허용), hold_reason: null 또는 공백 아닌 문자열.
- summary: 문자열 배열. READY standard는 공백 아닌 정확히 3줄; READY gallery는 0~3줄. HOLD는 빈 배열, hold_reason 필수. READY는 source_text 공백만 금지, hold_reason=null.
- category: 공백 아닌 문자열. 기존 gold category를 임의 번역/변경하지 않는다. 갤러리 분류 체계의 프롬프트 설계는 후속이다.
- tags: object {technical_form: list[str], practicality: list[str], difficulty: list[str]}. 원소는 공백 아닌 문자열.
- event_id: null 또는 공백 아닌 문자열. 아직 묶이지 않았으면 null.
- evidence_terms: list[str]; new_concepts_detected: list[str]; concept_usage: list[str]; actionable_idea: list[str]; is_pure_noise: 엄격 bool.
- evidence_terms/new_concepts_detected는 중복 금지(대소문자 무시). 각 용어는 source_text의 대소문자 무시 부분 문자열로 실제 존재해야 한다. new_concepts_detected는 evidence_terms의 부분집합이어야 한다.
- is_pure_noise=true이면 evidence_terms/new_concepts_detected/concept_usage/actionable_idea는 모두 빈 배열. HOLD에서는 분석 필드(summary, 세 tags 배열, evidence_terms, new_concepts_detected, concept_usage, actionable_idea)는 비우고 event_id=null, is_pure_noise=false. HOLD를 잡담 판정으로 오인하지 않는다.

`AnalysisResult.validate_known_concepts(known: KnownConcepts) -> None`: new_concepts_detected에 사전 등재 용어가 있으면 ValueError. 모델의 원문 근거 검증과 사전 대조를 별도 호출로 구분한다. known 비교는 strip+casefold, 원문 출력값 자체를 변조하지 않는다. 모든 근거 단어가 신개념일 필요는 없다.

KnownConcepts JSON: {schema_version: 1, provenance: 'initial_synthetic_draft', concepts: list[str]}. concepts는 비어 있지 않은 목록, 각 원소는 공백 아닌 문자열, strip+casefold 중복 금지. config 초안은 tests/blackbox/fixtures/gold_samples.json의 known_concepts 12개와 동일한 집합으로 시작한다. 사용자 실제 지식이 확인된 것처럼 표현하지 않는다. load_known_concepts는 호출자가 지정한 파일만 읽고 모델을 반환, 없는 파일/손상 JSON/검증 오류를 숨기지 않고 파일 생성·덮어쓰기 금지.

## 예시 및 경계
READY gallery: source_text='transformer 어텐션 실습', category='practical_experiment', evidence_terms=['transformer','어텐션'], new_concepts_detected=['어텐션'], concept_usage=['어텐션 실습'], actionable_idea=[], summary=[], tags 세 배열=[], event_id=null, is_pure_noise=false (기타 식별 필드 포함).
빈 텍스트+OCR 대기는 HOLD로 명시한다. 본문 충분성의 글자 수 임계값/LLM 분류 정확도/자연어 주장 전체의 근거성은 이 스키마로 입증하지 않는다. metrics는 계약에 넣지 않고 기존 원문 None/0를 보존한다. concept_usage/actionable_idea 문장 전체의 의미 검증은 후속 Evaluator의 책임이다.

## 완료 증거
1. 시작 전/완료 후 `uv run python -m unittest discover -s tests` exit 0. MCP 포함 검증은 `uv run --extra processing --extra mcp python -m unittest discover -s tests` exit 0; skip 수를 숨기지 않는다.
2. 새 공개 API로 READY 두 track, HOLD, JSON 왕복, model_json_schema 생성, 누락/추가 키, bool/문자열 coercion, 버전/플랫폼/track 오류, 공백/중복, 원문에 없는 개념, 사전 등재 신개념 거부, 순수 잡담 환각 거부를 검증한다. 긴 한글/이모지 및 대소문자, 없는/손상 사전 파일도 임시 fixture로 확인한다.
3. 기존 gold의 known_concepts와 config 초안 집합 일치 확인. gold의 expected.analysis는 부분 정답이므로 새 envelope에 그대로 파싱됐다고 주장하지 않는다.
4. `git diff --check`, 허용 파일만 커밋. 보고서에 명령/exit/수치/변경 파일/의존성 근거/미검증을 기록하고 worker_done으로 커밋 반환.

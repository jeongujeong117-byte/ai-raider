## 외부 계약 및 필수 공격
- `HealthState(str,Enum)`의 정확한 4값 HEALTHY/RATE_LIMITED/SESSION_EXPIRED/BLOCKED_FALLBACK. 초기 HEALTHY.
- `RateLimited(retry_after=60)`은 유한한 0 이상 숫자만 허용(bool/NaN/inf/음수/문자열 거부). `SessionExpired`, `Blocked`, `SupervisorStopped` 공개.
- `Supervisor(source,state_path=None,*,clock=None)`; 빈 source 거부, snapshot은 source/state/updated_at/retry_at/reason. 시간은 epoch, reason은 비밀 없는 고정 코드. import만으로 스레드/수집 없음.
- `run(operation,*,stop=None,fallback=None,max_retries=3)` : 결과 그대로 반환. 성공 HEALTHY, RateLimited는 RATE_LIMITED와 retry_at 기록 후 stop.wait로 중단 가능한 대기 및 추가 재시도 최대 max_retries. bool/음수/비정수 한도 거부. max_retries=0과 3을 확인하고 영원한 제한도 한정 종료. mock clock/Event 사용, 실제 sleep 금지.
- stop이 처음부터 설정되었거나 대기 중/재시도 직전에 설정되면 SupervisorStopped 및 추가 operation 금지. operation이 Blocked를 올리며 stop을 설정한 경우에도 추가 fallback 호출이 허용되는지 안전한 중단 의미와 spec을 대조해 보고한다.
- SessionExpired는 즉시 중단, 재시도/우회 없음. Blocked는 BLOCKED_FALLBACK, callback 있으면 1회 fallback. 성공해도 우회 상태 유지. callback 없으면 Blocked. fallback 실패는 무한 재시도 금지, fallback의 RateLimited/SessionExpired는 대응 상태 기록 후 재시도 없이 올린다.
- 일반 예외는 재시도 없이 전달하고 원시 메시지를 snapshot/파일/출력에 넣지 않는다. 비밀 문자열은 합성값만 사용한다.
- source별 전용 JSON 파일 원자 저장·복원. 깨진 JSON/잘못된 state/source 불일치/잘못된 timestamp·retry_at·reason 등 손상 파일은 안전 ValueError로 거부하고 덮어쓰지 않는다. reason에 임의 비밀 문자열을 삽입해 복원 경로가 고정 코드 계약을 지키는지도 확인한다. 디스크 저장 실패/replace 실패를 숨기지 않고 임시 파일 정리.
- source 간 격리 확인. 동일 파일 다중 작성자는 이번 보장 범위 밖이며 일부러 공유시켜 요구사항으로 확대하지 않는다.

## 완료 증거 및 판정
`uv run python -m unittest discover -s tests -v`(기존+개발 66개), `uv run python -m unittest discover -s tests/blackbox -v`(기존 7개+신규), `git diff --check` 실행. 각 종료 코드와 실제 수 보고. 기존 수집 기능의 None/빈 본문/KST/재개/대용량 회귀는 기존 T-000 검증도 재실행하여 확인하고 이 모듈 고유 검증과 구분한다. 화면 없는 기반 모듈이므로 브라우저 불필요.

FAIL은 재현 명령·최소 입력·기대값·실제값을 보고. spec의 명시적 계약 위반과 권고 사항을 구분하고 고치는 방법만 제안한다. 필수 검증 미완료는 PASS로 처리하지 않는다. 허용 파일만 커밋하고 handoff/reviews/T-001-qa.md에 PASS/FAIL, 검증한 개발 커밋, 명령·종료 코드·테스트 수, 미확인 사항을 적은 후 worker_done으로 QA 브랜치·커밋·보고서·판정을 S0에 반환한다.

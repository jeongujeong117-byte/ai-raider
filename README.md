# AI Raider — Instagram·X 수집 관리

기간과 계정을 선택해 게시물 본문·원문·작성일·확인 가능한 반응을 로컬 SQLite에 모으는 로컬 프로그램입니다. 기본 기간은 실행 시점으로부터 **달력 기준 3개월 전**이며 날짜 선택은 한국시간, 종료일 포함입니다. 초기 계정 62개를 제공하며 계정 일괄 추가, 플랫폼별 분류와 필터를 지원합니다.

## 시스템 구성과 AI 연결

계정 목록 → 기간별 수집 → 게시물·반응 저장 → 화면 조회·내보내기 순서입니다. AI 키·유료 API 계약 없이 시작합니다. 요약·주제 분류·사건 묶기는 이후 저장된 자료에 적용하면 됩니다. 원문을 먼저 남겨야 요약 오류와 수집 누락을 구분할 수 있습니다. 파일 저장 후 본문·이미지·영상·음성을 판별하고 로컬 OCR·전사 대기열에서 처리합니다. 원본과 추출 결과의 공통 키는 `(platform, post_id)`입니다.

- Instagram: [Instaloader Python API](https://instaloader.github.io/as-module.html)의 세션 재사용·프로필 게시물 순회를 사용합니다.
- X: [twscrape](https://github.com/vladkens/twscrape)의 인증 세션·날짜 검색·페이지 순회를 사용합니다. X 공식 유료 API가 아닌 웹 엔드포인트 기반 수집기입니다.
- 화면: Python 표준 라이브러리 로컬 서버. 별도 웹 서비스 계정이 필요 없습니다.
- 상용 관리형 대안은 [Apify의 Instagram Scraper](https://apify.com/apify/instagram-scraper) 등입니다. 이번 구현은 로컬 세션과 데이터 보관을 직접 관리하는 구조를 선택했습니다. 어느 도구도 삭제·숨김·검색 제한까지 포함한 전체 과거 자료 확보를 보장하지 않습니다.

## 설치·실행 (Windows PowerShell)

Python 3.11 이상과 uv가 필요합니다. 프로젝트 폴더에서:

```powershell
uv sync --extra processing
uv run --extra processing python raider.py check
.\start.ps1
```

브라우저에서 [수집 관리 화면](http://127.0.0.1:8765)을 엽니다. 포트 변경: `uv run --extra processing python raider.py serve --port 8766`.

의존성 설치 전에도 Python으로 `python raider.py serve`를 실행하면 계정·화면·저장소를 확인할 수 있습니다. 실제 수집은 두 라이브러리가 설치되어야 합니다.

## 로그인 — 본인 컴퓨터에서 설정

### Instagram

```powershell
uv run python raider.py login-instagram
```

터미널의 아이디·비밀번호 입력 안내에 따릅니다. 세션은 `.private/instagram.session`에 저장됩니다. 인증 확인이 요구되면 Instagram에서 정상 로그인·확인을 완료한 후 다시 실행하세요. 인증 문제를 우회하거나 자동으로 CAPTCHA를 해결하지 않습니다.

### X

프로젝트 폴더에서 다음 명령을 실행합니다. 먼저 `.private` 폴더를 만듭니다.

```powershell
New-Item -ItemType Directory -Force .private
uv run twscrape --db .private/x-accounts.db add_cookie my_account
```

twscrape의 안내에 따라 본인 X 브라우저 세션의 `auth_token`, `ct0`를 포함한 Cookie 헤더를 **터미널의 비공개 입력**으로 전달합니다. 쿠키를 채팅·소스 코드·스크린샷에 넣지 마세요. 자세한 형식은 [공식 Cookie 설정 안내](https://github.com/vladkens/twscrape#start-with-cookies)를 따릅니다. 실행 버전에 `add_cookie`가 없다면 `uv sync --upgrade-package twscrape` 후 인자 없이 `uv run twscrape`를 실행해 명령 목록을 확인하세요.

`.private`에는 로그인 권한이 있는 세션이 저장되므로 공유하지 않습니다. `.private/`와 `data/`는 Git에서 제외했습니다. 화면에는 세션 내용이 노출되지 않습니다. 세션 파일 존재와 로그인 유효성은 별개입니다.

## 사용 방법

1. 계정·분류 관리에서 플랫폼과 분류를 선택하고 `@first @second` 또는 `@first@second`를 붙여넣습니다. 줄바꿈·쉼표·같은 플랫폼의 프로필 링크도 지원합니다. 등록 전 확인 → 새 계정 추가 순서입니다. 중복은 건너뛰고 잘못된 항목이 있으면 전체 등록을 보류합니다. 기존 계정의 분류는 그대로 유지합니다.
2. 계정과 기간을 선택합니다. 초기 목록은 후보 포함 **62개 전체**이며 개별 체크를 바꿀 수 있습니다. 플랫폼·분류를 좁힌 경우 **화면에 보이는 체크된 계정만** 수집합니다. 추가한 계정은 기본 선택되지만 현재 필터에 따라 안 보일 수 있습니다.
3. ‘수집 시작’을 누릅니다. 한 작업만 실행됩니다. 먼저 계정 하나로 로그인과 라이브러리 호환성을 확인하는 편이 좋습니다.
4. 화면을 닫아도 서버가 실행 중이면 계속 수집합니다. Python 프로세스를 끄면 중단됩니다.
5. 중지 후 같은 작업의 ‘이어받기’를 누르면 완료된 구간은 건너뛰고 미완료 구간을 다시 조회합니다. 종료 기간은 원래 작업 값이 유지됩니다.
6. 게시물은 수집 중에도 확인하며 플랫폼·계정 분류·계정별 최신순/좋아요순 조회와 CSV·JSON 내보내기를 제공합니다. 좋아요순은 플랫폼을 선택했을 때 적용합니다. 결측 반응은 0으로 바꾸지 않습니다.

## 수집 범위와 완료 상태

- Instagram은 고정 게시물·정렬 예외 때문에 오래된 게시물 하나를 만났다고 종료하지 않고 프로필의 전체 제공 목록을 순회한 후 날짜로 필터링합니다. 따라서 과거 게시물이 많은 계정은 오래 걸립니다. 중단한 Instagram 계정은 목록 처음부터 재탐색하며 DB의 고유 키로 저장 중복을 막습니다. 페이지 커서 자체를 영구 복원하는 방식은 아닙니다.
- X는 UTC 날짜별 검색 구간을 저장하고, 결과를 정확한 한국시간 요청 범위로 다시 필터링합니다. 완료된 날짜는 재개 시 건너뜁니다. 검색이 제공하지 않은 항목·삭제글·일부 재게시는 누락될 수 있습니다.
- ‘조회 종료·완전성 미검증’은 수집기의 목록/검색이 끝났다는 뜻입니다. 0건도 ‘과거 글이 실제로 없음’이 아닌 ‘이번 조회에서 반환된 글 없음’입니다.
- 오류가 나면 해당 플랫폼의 후속 요청을 중단하고 다른 플랫폼을 진행합니다. 이미 저장된 자료는 남습니다. 재개는 로그인·접근 문제를 해결한 뒤 실행합니다.
- 본문과 반응은 저장 시점 기준입니다. AI 관련 글인지·한국어인지로 수집 단계에서 버리지 않습니다. 혼합 게시물의 언어·주제 분류는 후속 처리입니다.
- ‘이미지·영상 파일도 저장’은 기본 켜짐입니다. Instagram 이미지·캐러셀·제공되는 영상, X 사진·영상·움직이는 미디어와 썸네일을 저장합니다. X 영상은 제공된 MP4 중 가장 높은 비트레이트를 선택합니다. 플랫폼이 원본 해상도를 제공한다는 보장은 없습니다.
- 파일당 512MB 제한입니다. 파일은 `data/media/플랫폼/h-계정/p-게시물ID/`에 저장하고 게시물에 로컬 경로·크기·상태를 기록합니다. 새 다운로드에는 SHA-256도 기록합니다. 완료 파일은 재사용하며 미완료 전송 파일은 지웁니다.
- 파일 저장 실패 시 본문·반응·참조는 남고 ‘조회 종료 · 파일 저장 오류’로 표시합니다. 같은 작업을 이어받으면 해당 계정/날짜 구간을 재조회해 파일 주소를 갱신하고 재시도합니다. 파일 주소 만료, 접근 제한, 삭제된 글은 재시도로도 해결되지 않을 수 있습니다.
- 체크를 끄면 파일 주소만 저장합니다. 기존 작업을 이어받을 때는 **원래 작업의 파일 저장 설정**을 사용합니다. 이전 버전에서 생성한 작업은 주소 저장 모드로 유지되므로 파일을 받으려면 저장 옵션을 켜서 새 작업을 시작하세요.
- 파일 종류를 자동 판별해 이미지 OCR, 영상·음성 전사, 영상 화면 OCR을 실행합니다. 이미지 의미 설명·댓글 본문·스토리·개인화·AI 요약은 포함하지 않습니다.

## 데이터와 설정

- `config/sources.json`: 계정과 분류. 화면에서 추가·수정하면 저장되어 재시작 후에도 유지됩니다.
- `config/categories.json`: 플랫폼별 사용자 분류. 처음 새 분류를 추가할 때 생성됩니다. 기본 분류는 `source_manager.py`에 있습니다.
- `data/media/`: 분석 전 이미지·영상 파일. 다운로드된 파일은 게시물 카드에서 열 수 있습니다.
- `data/raider.sqlite`: 게시물, 반응, 작업과 날짜 구간 상태.
- `.private/`: 본인 로그인 세션. 기본 저장은 암호화된 금고가 아닌 로컬 파일입니다.

라이브러리·플랫폼 변경과 로그인 제한으로 수집이 실패할 수 있습니다. 이 저장소의 로컬 테스트와 실제 플랫폼 로그인 후 수집 검증은 별개이며, 실제 수집은 사용자 세션 연결 후 확인해야 합니다.

## 파일 추출·OCR·전사와 코랩의 차이

| 하려는 일 | 방법 | AI 필요 여부 | 현재 구현 |
|---|---|---|---|
| 게시물 본문·반응 읽기 | 수집 라이브러리 | 필요 없음 | 포함 |
| 이미지·영상 파일 받기 | HTTP 다운로드 | 필요 없음 | 포함 |
| 영상 읽기·프레임 추출 | PyAV(FFmpeg 라이브러리) | 필요 없음 | 포함 |
| 제공되는 자막 텍스트 받기 | 자막 데이터 읽기 | 새로 인식할 필요 없음 | 현재 수집기에 미포함 |
| 이미지·영상 화면 속 글자 읽기 | Tesseract 한국어·영어 OCR | 로컬 인식 엔진, 유료 API 불필요 | 포함 |
| 음성에서 글자 만들기 | faster-whisper small | 로컬 음성 인식 AI, 유료 API 불필요 | 포함 |
| 이미지의 의미 설명·소식 요약 | 이미지 이해·언어 모델 | 모델 사용 선택 | 후속 단계 |

코랩은 Python/Jupyter 코드를 실행하는 환경입니다. 코랩에서 실행하는 프로그램도 내부적으로 OCR·Whisper 모델을 사용할 수 있으므로 ‘코랩 = AI를 쓰지 않음’은 아닙니다. 제공된 수업 자료 「2. Basic web data scraping」50~54쪽은 yt-dlp 다운로드, 55~57쪽은 Whisper 로컬 전사 예제입니다. 현재 프로그램은 수집·파일 보관 후 로컬 OCR/전사를 적용하며 필요할 때만 생성형 AI 요약을 연결하는 구조입니다. 영상에 박힌 자막은 별도 자막 파일과 달리 OCR이 필요합니다.

공식 근거: [Colab FAQ](https://research.google.com/colaboratory/intl/en-GB/faq.html), [Instaloader 다운로드 옵션](https://instaloader.github.io/cli-options.html), [Tesseract OCR](https://github.com/tesseract-ocr/tesseract), [faster-whisper](https://github.com/SYSTRAN/faster-whisper).

## 플랫폼별 기본 분류

- Instagram: 미분류, AI 소식, 업무·생산성, 개발·에이전트, 연구·교육, 마케팅·사업, 이미지·영상, 로봇·산업.
- X: 미분류, 공식 발표, 뉴스·큐레이션, 프롬프트·활용, 개발·도구, 연구·평가, 산업·정책.

이는 **계정의 분류**이며 게시물마다 AI로 판정한 주제가 아닙니다. 기존 계정 소개 정보가 있는 경우 간단한 키워드 규칙으로 초깃값을 제안하고 정보가 없으면 미분류로 둡니다. 플랫폼별 새 분류 추가와 계정별 수정이 가능합니다. 분류는 계정 관리·조회에 사용하며 수집 중 게시물 주제나 개인 반응으로 거르지 않습니다.


## 자동 추출과 게시글 묶음 (v0.3)

설치 시 `uv sync --extra processing`을 사용하고 다음 명령을 한 번 실행해 공개 모델을 내려받습니다.

```powershell
uv run --extra processing python raider.py prepare-processing
.\start.ps1
```

현재 작업 환경에는 한국어·영어 OCR과 Whisper small 모델 준비를 완료했습니다. 모델은 `data/models/`에 보관하며 다른 컴퓨터로 옮기면 다시 준비해야 합니다. 유료 AI API 키가 필요 없으며 게시물 파일을 외부 AI 서비스에 업로드하지 않습니다. 첫 준비에는 약 500MB의 모델 다운로드가 있습니다. 운영 중에는 로컬 모델만 사용합니다.

### 처리 순서

1. 수집 범위에 맞는 게시물 본문·반응·원문 주소·첨부 목록을 먼저 저장합니다.
2. 파일 저장 옵션을 켜면 첨부 파일을 받고 실제 파일 형식으로 이미지·영상·음성을 판별합니다. 본문이 함께 있으면 혼합 게시글로 표시합니다.
3. 본문은 그대로 보존합니다. 이미지는 Tesseract(`kor+eng`, 문단 모드), 영상은 faster-whisper small(CPU int8, 언어 자동 감지)와 PyAV 화면 추출·OCR, 음성은 Whisper 전사로 처리합니다. 영상에 음성 트랙이 없으면 전사를 생략한 상태를 기록하고 화면 처리는 계속합니다. 움직이는 GIF도 영상 경로로 처리합니다.
4. 영상 화면은 5초 간격, 최대 300장 표본입니다. 원본 영상은 그대로 남습니다. 상한 이후 화면은 미처리라고 표시합니다. 음성 전사에는 이 화면 표본 상한을 적용하지 않습니다. 순간 자막·복잡한 화면·OCR 오독·무음/잡음 전사 오류가 있을 수 있으며 추출 결과는 원문 검증 대상입니다.
5. 본문, 첨부 순서, 이미지 OCR, 전사 시간 구간, 화면 OCR 시간, 도구·상태·오류를 동일한 `(platform, post_id)` 아래 보관합니다. 카드뉴스와 영상이 섞여도 게시글이 분리되지 않습니다. 다른 플랫폼의 같은 ID는 다른 게시글입니다.
6. 별도의 로컬 작업 대기열이 순차 처리하므로 수집은 긴 영상 전사를 기다리지 않습니다. 앱이 켜져 있어야 처리가 진행됩니다. 서버 재시작 시 미완료 작업을 다시 시도하고, 처리 기능 설치 전 수집한 글도 자동 등록합니다.
7. 첨부 하나의 실패가 다른 첨부 처리를 막지 않습니다. 모델 누락·원본 다운로드 실패는 확인 필요 상태로 남습니다. 모델 준비 후 ‘저장된 게시글 전체 처리·재시도’ 또는 각 카드의 ‘다시 처리’를 누릅니다. 원본이 없는 경우 먼저 수집을 재시도해야 합니다.

재수집해도 별도 `processing` 테이블의 추출 결과를 삭제하지 않습니다. 입력 파일이나 본문이 바뀌면 새로 처리하고 동일 입력의 완료 결과는 재사용합니다. 수동 재처리는 해당 게시글의 추출 작업 전체를 다시 실행합니다. 진행 중인 한 파일의 추출 결과는 중지/재시작 후 다시 계산할 수 있습니다.

게시물 카드의 ‘본문·추출 내용 함께 보기’와 첨부별 상세에서 결과를 확인합니다. 조회 버튼으로 목록을 갱신하면 최신 결과가 표시됩니다. JSON에는 원본과 모든 구조화된 추출 결과를 포함하고 CSV에도 미디어·추출 결과를 JSON 셀로 함께 내보냅니다. 단순 글·파일 형식 분류이며, 내용 의미를 추측하는 이미지 이해 모델은 사용하지 않습니다.

## GitHub 전담 에이전트 (v0.4)

[GitHub 수집 화면](http://127.0.0.1:8766/github)을 사용합니다. 기본 실행 포트 8765이면 `/github` 경로도 같은 포트로 엽니다. Instagram·X와 별도 작업·중지·재개 상태를 가지며 서로의 수집을 막지 않습니다.

### 래퍼 선택

[PyGithub](https://pygithub.readthedocs.io/en/stable/introduction.html)를 선택했습니다. 공식 REST API의 검색·페이지 조회·저장소·릴리스를 Python으로 읽는 래퍼입니다. [github3.py](https://github.com/sigmavirus24/github3.py)도 대안이며, 이번에는 기존 Python 구조에 PyGithub를 연결했습니다. 파일은 API에서 확인한 기본 브랜치 커밋 SHA에 고정한 GitHub codeload ZIP을 스트리밍으로 받습니다. 브라우저 스크래핑이나 AI 모델은 필요하지 않습니다.

### 대상 범위 → 추출 도구 → 분류 도구

| 대상 범위 | 추출 도구 | 분류 도구 |
|---|---|---|
| 누적 스타가 많은 AI·에이전트·MCP·스킬 저장소 | PyGithub repository search, 검색식별 스타 내림차순 | 소개·토픽·README 키워드 규칙 |
| 직접 지정한 공개 저장소 | PyGithub get_repo, URL/owner-repo 일괄 입력 | 같은 규칙 + 화면에서 수동 수정 |
| 기본 브랜치의 특정 커밋 파일 | SHA로 고정한 codeload ZIP, 파일 전체 목록 | SKILL.md 경로 탐지, 문서/예제 구분 |
| README·문서·스킬 파일 | ZIP에서 제한된 크기의 텍스트 읽기 | 저장소 두 분야 및 개별 스킬 두 분야 초안 |
| 최근 릴리스 | PyGithub releases, 최대 100개 검사 후 기준일 필터 | 원래 저장소에 연결 |
| 최근 관심 변화 | 한국시간 날짜별 스타 관측 SQLite | 실제 관측 날짜 사이 증가량, 스킬 여부 필터 |

분류는 **컴퓨팅 기술 / 분야별 실무 활용** 두 가지입니다. 혼합 신호 또는 근거 부족은 검토 필요로 표시합니다. 저장소 수동 분류는 재수집 후에도 유지합니다. 스킬은 SKILL.md 파일을 실제 확인하면 확정, 이름·소개에 skill이 있으면 후보입니다. ZIP을 끄면 파일별 스킬 확정 탐지는 수행하지 않습니다. 개별 스킬 문서의 분류는 텍스트 규칙이며 실사용 적합성을 인증하지 않습니다.

### 수집 모드

- **기존 인기**: 생성일 제한 없이 누적 스타순 발견. 기본 스타 하한 1,000, 검색식당 상위 100건, 기본 검색식 8개. `config/github.json` 또는 화면에서 변경합니다.
- **최근 생성**: 기준일 이후 새로 생성된 저장소를 스타순 발견합니다. 스타 급증 순위가 아닙니다.
- **재관측**: 이미 수집한 저장소를 다시 읽고 스타·현재 파일·문서·릴리스를 갱신합니다. 검색식·스타 하한·직접 지정 값은 이 모드에 적용하지 않습니다.

처음 관측한 날에는 과거 스타 증가량을 알 수 없으므로 대기로 표시합니다. 날짜가 다른 관측이 두 번 이상 생기면 최근 7일 내 가능한 관측을 우선 비교하며, 없으면 직전 관측을 비교합니다. **증가량과 실제 비교 일수·날짜를 함께 표시**합니다. 같은 날 여러 번 조회하면 그날의 마지막 수치를 보관합니다. 별도 정기 실행은 아직 등록하지 않았습니다.

### 파일·검색의 한계와 저장

- 공개 저장소만 지원합니다. 인증은 선택사항이며 서버를 실행하는 환경의 `GITHUB_TOKEN` 또는 `GH_TOKEN`을 읽습니다. 토큰을 화면이나 소스에 저장하지 않습니다.
- GitHub 검색식 하나당 최대 1,000건입니다. 1~1,000건으로 수집 상한을 지정하고, 더 많은 범위가 필요하면 서로 다른 토픽·키워드·생성일·스타 구간으로 검색식을 나눕니다. 한 작업은 최대 20개 검색식을 지원합니다. 저장소 중복은 합치지만 전체 GitHub의 완전 수집을 보장하지 않습니다.
- 여러 `owner/repo` 또는 GitHub 프로필이 아닌 **저장소 주소**를 공백·줄바꿈·쉼표로 붙여넣을 수 있습니다. 직접 지정은 스타·날짜 하한과 관계없이 받습니다. 직접 지정만 받으려면 검색식을 비우세요.
- 파일은 **기본 브랜치의 현재 커밋 스냅샷**입니다. 전체 커밋 역사·다른 브랜치·별도 릴리스 바이너리·서브모듈 내용·외부 LFS 파일은 별도로 받지 않습니다. ZIP을 자동 압축 해제하거나 저장소 코드를 실행·설치하지 않습니다.
- ZIP 전송 상한은 저장소당 기본 512MB, 설정 범위 1~4096MB입니다. 미완성 전송은 삭제합니다. 같은 SHA의 완료 ZIP은 재사용합니다. 서로 다른 커밋 ZIP은 보존하고 화면에서는 최근 조회한 버전을 연결합니다.
- 파일 목록은 최대 100,000건, 문서 읽기는 최대 200개·전체 8MB·문서당 256KB입니다. 큰 문서나 읽기 상한은 경고/잘림 상태로 남습니다. ZIP 안에는 GitHub가 제공한 나머지 파일도 포함합니다. 문서만 일부 읽는 것과 ZIP 파일 저장 완료를 구분합니다.
- 릴리스는 최근 기준일 이후 항목을 저장하되 최대 100개만 검사합니다. API 정렬을 발행일순으로 가정하지 않고 검사 범위 안에서 필터링합니다.
- 403/429 요청 제한을 감지하면 요청을 계속 보내지 않고 멈춥니다. 시간이 지난 뒤 ‘이어받기’를 누르면 완료 검색·저장소를 건너뛰고 미완료 부분을 재조회합니다. 작업 상태와 상세 오류에 인증 문자열을 노출하지 않습니다.
- `data/github/github.sqlite`: 저장소·분류·일별 스타·작업 상태. `data/github/archives/`: 커밋별 ZIP. 저장소 상세의 문서·파일 목록·릴리스와 묶음 JSON 내보내기를 제공합니다.

### 터미널 사용 예시

```powershell
# 지정한 저장소만 ZIP까지 수집
uv run --extra processing python raider.py github --repos "anthropics/skills"
# 기본 검색식으로 누적 스타 상위 탐색
uv run --extra processing python raider.py github --min-stars 1000 --limit-per-query 100
# 검색식 지정, 파일 없이 소개·README·릴리스만
uv run --extra processing python raider.py github --query "topic:ai-agents" --limit-per-query 20 --metadata-only
# 수집한 저장소의 스타 재관측
uv run --extra processing python raider.py github --mode watch
# 미완료 작업 재개
uv run --extra processing python raider.py github --resume 작업ID
```

터미널 명령과 서버에서 같은 GitHub 작업을 동시에 실행하지 마세요. 단일 서버 안에서 Instagram·X와 GitHub 에이전트를 동시에 실행하는 것은 지원합니다.

## 나머지 정보원 전담 추출기 (v0.5)

[정보원별 추출 화면](http://127.0.0.1:8766/sources)에서 유튜브·뉴스·허깅페이스·AI 활용 갤러리를 선택합니다. 서버 포트가 8765면 같은 `/sources` 경로를 사용합니다. 각 정보원은 독립된 실행·중지·이어받기 상태를 갖고 결과는 공통 게시글 저장소와 OCR/전사 대기열로 보냅니다.

| 대상 범위 | 추출 도구 | 분류·후처리 |
|---|---|---|
| YouTube 채널·재생목록·개별 영상 | yt-dlp 공식 Python 래퍼, 제공 자막·영상 정보·선택적 영상 파일 | 주제 키워드 초안, 파일 확보 시 Whisper·영상 화면 OCR |
| 뉴스 RSS/Atom·개별 기사 | feedparser + Trafilatura + BeautifulSoup | 주제 키워드 초안, 이미지 OCR |
| Hugging Face 모델·데이터셋·Spaces | 공식 huggingface_hub HfApi | 모델/데이터셋/Space 구분, 주제 초안, 카드·파일 목록 묶음 |
| AI 활용 갤러리 | 공개 게시판 HTML + BeautifulSoup, 페이지 순회 | 본문·반응·첨부를 게시글별로 묶고 OCR/전사 |
| 뉴스·갤러리의 공개 요청 실패 | 선택형 Playwright + 수집용 Edge 프로필 | 같은 추출기·분류기 재사용 |

래퍼 근거: [yt-dlp](https://github.com/yt-dlp/yt-dlp), [YouTube 실행 환경](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [feedparser](https://feedparser.readthedocs.io/en/latest/), [Trafilatura](https://trafilatura.readthedocs.io/en/latest/usage-python.html), [HfApi](https://huggingface.co/docs/huggingface_hub/package_reference/hf_api). 갤러리 전용 비공식 패키지 대신 게시판 HTML 구조를 직접 읽습니다.

### 설치·실행

```powershell
uv sync --extra processing --extra browser
.\start.ps1
```

YouTube용 공식 권장 `yt-dlp[default]` 의존성을 설치하고 PATH의 Node.js를 사용할 수 있으면 yt-dlp 실행 환경에 연결합니다. Node 22 이상 또는 yt-dlp가 지원하는 다른 실행 환경이 필요할 수 있습니다. 이 프로젝트 환경의 Node 24를 확인했습니다. 소스 자료에 포함된 임의 코드를 실행하거나 설치하지 않습니다.

대상은 `config/other_sources.json`에서 관리합니다. 화면에서 줄마다 URL/ID를 붙여넣으면 **해당 작업의 설정**으로 저장되며, 기본 목록을 바꾸려면 설정 파일을 수정합니다. 기본 예시는 OpenAI YouTube 채널, AI타임스 RSS, Hugging Face models/datasets/spaces, AI 활용 갤러리 ai_utilize입니다. 사용자가 확정한 전체 채널·언론 목록이라는 뜻은 아닙니다.

- 기본 최근 달력 3개월, 종료일 포함 한국시간입니다. 건수·페이지·파일 크기 상한을 설정합니다. 날짜를 확인하지 못한 항목은 날짜 미확인으로 보존합니다.
- YouTube는 목록 상한까지 영상별 정보를 읽습니다. 한국어/영어 JSON3 제공 자막을 우선 읽고 영상 파일 저장을 선택하면 다운로드해 로컬 전사·화면 OCR으로 보냅니다. 제공 자막 HTTP 오류, 파일 접근·다운로드 제한은 명시적으로 남깁니다. 영상 댓글 본문은 포함하지 않으며 확인 가능한 댓글 수만 저장합니다.
- 뉴스는 RSS가 제공하는 범위만 발견합니다. 과거 3개월 전체를 보려면 언론사 아카이브·추가 피드·개별 기사 URL도 필요합니다. 본문 실패 시 피드 요약을 보존하고 부분 실패를 표시합니다. 기사 날짜와 피드 날짜를 확인하며 전체 글을 추출했다고 거짓 표시하지 않습니다.
- Hugging Face 대상 형식은 `models`, `datasets`, `spaces`, 또는 `model:owner/name`, `dataset:owner/name`, `space:owner/name`입니다. 목록은 좋아요순이며 마지막 수정일로 기간을 필터링합니다. 현재 커밋·전체 API 파일 목록과 카드/주요 설정 문서(최대 20개·파일당 1MB)를 받습니다. 모델 가중치·전체 데이터셋·실행 코드는 자동 다운로드/실행하지 않습니다. 이 범위는 화면과 각 결과에 기록합니다.
- 갤러리는 [AI 활용 마이너 갤러리](https://gall.dcinside.com/mgallery/board/lists/?id=ai_utilize) 공개 목록·본문·추천·조회수·직접 노출된 이미지/동영상을 받습니다. 기본 최대 100페이지, 대상당 건수 상한을 적용합니다. 오래된 고정 공지 하나만 보고 중단하지 않습니다. 댓글·외부 임베드 플레이어·삭제/비공개 글의 전체 복원은 지원하지 않습니다.
- 본문·첨부·제공 자막·추출 결과는 같은 `(platform, post_id)`에 연결합니다. 이미지·영상 미디어는 파일당 기본 512MB 상한, 스트리밍 저장·전송 중단 정리를 사용합니다. 추출 실패해도 본문은 남습니다.
- 결과는 `/sources`에서 정보원별로 보고 JSON을 내보냅니다. 분류 필터는 현재 조회한 항목에 적용되며 더 보기로 추가 조회할 수 있습니다. 주제 분류는 컴퓨팅/분야별 실무의 키워드 초안으로, 의미 요약 모델은 아닙니다.

### 로그인·브라우저 보완

공개 API/HTML/RSS가 읽히면 브라우저를 띄우지 않습니다. 뉴스·갤러리의 브라우저 보완 옵션을 켜면 실패 시 별도의 Edge 프로필로 읽습니다. 브라우저 보완은 한 번에 하나씩 실행합니다. 본인 계정 인증이 필요한 경우:

```powershell
uv run --extra browser python raider.py source-browser-login "https://gall.dcinside.com/"
```

브라우저에서 사용자가 직접 로그인/인증하고 터미널에서 Enter를 누릅니다. 프로필은 `.private/source-browser/`에 보관합니다. 개인용 기존 브라우저 프로필을 복사하지 않습니다. 로그인 준비 명령과 서버의 브라우저 보완을 동시에 실행하지 마세요. 설치된 Microsoft Edge를 사용하므로 별도 Chromium 다운로드는 필요하지 않습니다. CAPTCHA·유료벽·접근 권한은 자동 우회하지 않습니다. 로그인 프로필 경로의 실제 인증 수집은 사용자 로그인 후 검증해야 합니다.

YouTube는 본인 Netscape 형식 쿠키를 `.private/youtube.cookies.txt`에 두면 yt-dlp가 사용합니다. 프로필 로그인 명령이 YouTube 쿠키 파일을 자동 생성하지는 않습니다. 파일 수집이 막히면 원문·오류 상태를 남기고 인증/도구 호환성 조정 후 이어받습니다. 어떤 방식으로도 원격 서비스가 제공하지 않는 파일까지 확보한다고 보장하지 않습니다.

### 터미널

```powershell
uv run --extra processing python raider.py source news --target "https://www.aitimes.com/rss/allArticle.xml" --limit 30
uv run --extra processing python raider.py source youtube --target "https://www.youtube.com/@OpenAI/videos" --limit 10
uv run --extra processing python raider.py source huggingface --target "model:openai/whisper-tiny" --limit 1
uv run --extra processing python raider.py source gallery --pages 100 --limit 1000
uv run --extra processing --extra browser python raider.py source news --target "기사URL" --browser
```

CLI는 수집을 수행하고 추출 대기열을 저장합니다. 수집 종료 시 남아 있는 OCR/전사는 서버를 실행하면 이어서 처리합니다. 같은 데이터 폴더를 사용하는 CLI와 서버를 동시에 실행하지 마세요. 단일 서버 안의 정보원별 동시 실행은 지원합니다.

### 검증과 실행 방식

2026-11-10: 단위 검사 50개, 전체 정보원 HTTP 통합 검사, 세 화면 JavaScript 문법 검사를 통과했습니다. 실제 공개 뉴스 1건의 본문·이미지 파일, 갤러리 게시글 1건, Hugging Face 모델 카드·파일 목록, YouTube 영상 정보 1건을 확인했습니다. YouTube 파일은 공식 권장 의존성과 Node 설정 보완 후 실제 65초 영상(약 2.8MB) 다운로드에 성공했습니다. 제공 자막은 HTTP 오류로 부분 실패를 기록하며 파일을 로컬 Whisper/화면 OCR으로 처리하는 경로를 사용합니다. 로그인된 브라우저 수집은 아직 미검증입니다. 따라서 모든 정보원의 모든 자료가 실제 확보됐다고 표시하지 않습니다.

30분마다 작업 완료 여부를 감시하는 예약은 만들지 않았습니다. 이번 실행 안에서 도구별 구현→검증→다음 도구로 진행했습니다. 구현 작업이 끝난 뒤 정기 자료 수집 주기를 설정하는 것은 별개입니다. 작업 단위별 이어받기 지시는 `research/SOURCE-WORK-UNITS.md`에 기록했습니다.

추가 실검증: 다운로드한 뉴스 이미지의 OCR 및 실제 65초 YouTube 영상의 로컬 Whisper 전사·화면 OCR이 모두 completed로 끝났습니다. 결과는 `data/verification-other/news-processed.json`, `youtube-processed.json`에 보관합니다. 테스트 자료는 실제 수집 게시글 DB에 섞지 않았습니다.
